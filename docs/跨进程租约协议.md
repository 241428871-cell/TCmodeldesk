## 持久合同

核心 `durable_leases` 复用原 `LeaseRequest` 和文件冲突判定，不引入服务、时钟、模型请求或费用授权。调用方提供同一个 SQLite 连接，在 `BEGIN IMMEDIATE` 事务内准入并提交；提交成功前不得启动工作器。普通导入和 `read/active` 不初始化表。

每张回执包含随机代次 token、原项目和任务、规范文件集合、账户桶与限额，以及控制器实例、PID、出生时间。启动后另存 launcher 的 PID 和出生时间。出生时间缺失、非正数或非有限数拒绝。进程身份的实际查询由宿主负责，核心不凭 PID 推断存活。

| 状态 | 含义 | 原控制器退出后能否自动回收 |
| --- | --- | --- |
| reserved | 已取得资源，尚未进入启动边界 | 仅当宿主证明这个确切控制器实例已退出 |
| armed | 已提交启动意图，可能已创建子进程 | 不允许；没有子进程回执也不能证明未启动 |
| started | 已登记确切 launcher | 不允许；父进程退出不代表子进程或其后代退出 |
| released | 已通过停止／完成证明释放 | 不再占资源，保留旧回执隔离迟到调用 |

每个修改以完整旧回执 CAS 更新。旧代次不能释放新代次；释放事务中断会回滚，保留原资源占用。没有 TTL、租约到期自动抢占或后台回收时钟。UNKNOWN、存储损坏、超出活动记录预算都拒绝继续准入。

多个工作台对同一数据库争抢时，文件重叠、嵌套项目、项目并发和账户并发使用同一准入事务。新设置提高上限不能覆盖仍在执行的旧回执所承诺的较低上限。不同文件和账户在限额内仍可并行。当前没有跨进程等待顺序或公平性保证。

`finish` 是宿主内部接口，要求宿主在事务内对确切回执提供静止证明。它不是给 HTTP、模型或用户输入直接调用的“强制解锁”开关。仅 `wait()` 返回、任务标记 completed、旧 owner 退出、心跳超时均不足以通用证明所有后代及写回已结束。核心测试的肯定验证器只验证事务合同，不冒充真实进程树验证。

## 下一轮生产接线顺序

1. 明确安装运行域的共享数据库位置，由安装根稳定解析；同一安装的所有宿主使用同一库。不得让调用者任意传库路径，不能将提示、密钥或账户原文写入租约。先在隔离 fixture 验证无导入副作用、路径替换／坏库拒绝；不同安装之间不能未经实现就宣称已互斥。
2. 在 `execution_leases` 中组合进程内等待队列和持久准入。等待发生在目标授权锁之外；每次数据库事务短暂持有，等待期间重查 STOP。不能持有 SQLite 写事务等待目标锁、CLI 或文件操作。跨进程等待状态需要进入现有面板快照，避免已被本地 broker 接纳却仍未启动时显示错误状态。
3. 在公共 `panel_server.execute_task` 中保存原任务租约 token；目标授权与费用重查保持原位。Popen 前先提交 armed，Popen 后登记 launcher。原任务队列与租约是不同事务，不宣称跨库原子；崩溃窗口一律保留占用，不能按另一个库的较早状态贸然重发。
4. 子工作器使用实际项目、文件、账户和 token 校验当前持有者；快照字符串不是持有证明。核对所有公共路径：Codex MCP、DSH loopback，以及 Claude/Codex、DSH/Pi、WorkBuddy、直接咨询、Aider 工作器。历史无 token 的运行须明确兼容与迁移边界。
5. 先实现并验证宿主静止证明，再允许自动释放 armed/started。包括启动失败、启动成功但 PID 回执失败、控制器退出而 worker 存活、worker 退出而原生子进程／测试后代存活、进程状态不可读、PID 复用等情况。无法证明就保留占用，汇入原待核对列表。不得用任务成功标志代替证明。
6. `cli_writeback.recover` 必须取得同一持久资源域的所有权，核对原进程后只恢复文件；处理原租约尚占用与恢复租约接管的 CAS，不能简单另建任务或先释放后无锁写。原目标授权 → 运行文件锁 → 写回的既有顺序需与短事务核对，避免反向锁序。
7. 全量离线回归后，再分别记录真实 CLI、安装迁移、进程强制终止恢复与人工验收。Windows、真实断电和硬件缓存级验证不在范围；SOURCE-MANIFEST 和发布收尾继续等待用户授权。

项目内原队列、费用账本、owner_epoch、独立验收、TCAUTO 单入口和 30 分钟周期保持。核心资源 token 与目标 owner_epoch 分别管资源持有和主脑身份，不可混用。
