# TCmodeldesk：Claude 界面与应用体验交接

本轮任务是完善一款可实际使用的 macOS 多智能体工作台。可以自由设计、调整信息架构、制作图标和重做交互；范围不限于换色或首页。请自行详细阅读源码、现有文档与真实界面，用 Git 状态和实际运行核对结论，不要把交接当作完整项目事实。

## 先核对项目

1. 阅读 `AGENTS.md`、`CLAUDE.md`、`docs/GIT_WORKFLOW.md`、`docs/CROSS_HOST_FEATURES.md`。
2. 阅读 `docs/完整软件设计.md`、`docs/重构进度.md`、`DESIGN.md`、`docs/macOS应用.md` 和 `docs/执行端来源验收.md`；进度包含历史决策，以最新用户决定及实际源码为准。
3. 自行查看分支、未提交差异和实际运行版本。保护已有成果；不要恢复旧时钟、自动暂存、重置或把本地 baseline 历史推到 GitHub。
4. 从路由、控制器和模型定义盘点功能，建立“后端能力—入口—状态—错误—验收”清单。后续每次功能变化都同步对应界面，不能只修改文档或新增一个未接线按钮。

## 当前成果

- 产品由 TCworkdesk 改名 **TCmodeldesk**；仓库为 <https://github.com/241428871-cell/TCmodeldesk>。README 与 THIRD_PARTY 明确引用原项目 <https://github.com/Gambler134201/multi-agent-collaboration>，原 MIT 版权保留。
- 原生外壳在 `desktop/macos/TCmodeldesk.swift`，使用 AppKit／WKWebView，自带冻结 Python、Node 和 acpx；后端业务源码与网页资源位于所选安装中。Codex／DSH 默认使用桌面应用附带的后台 CLI，可切独立 CLI；Claude 跟随电脑 CLI／cswap，不复制账户。
- 前端主要在 `.local-worker/panel/`，真实接口在 `panel_server.py`、`panel_routes.py` 与各业务模块。LangGraph／持久协议在 `control-plane/`，不要另造一套假状态。
- 原生应用采用 regular activation policy，保留程序坞入口，并通过 NSStatusItem 提供右上角菜单栏入口。关闭窗口保持应用运行；再次打开恢复窗口。退出或切换安装，先安全停止自己管理的空闲后台；忙碌、未结算或证据未知时阻止退出并展示原因。连接外部安装时只断开，不停止外部服务。
- 新安装默认数据为 `~/Library/Application Support/TCmodeldesk/Data`，旧 TCworkdesk 数据指针／目录兼容读取。原生菜单支持校验复制、一键切换、失败回退和保留旧副本。项目源码及 `.model-desk` 历史留在项目中，钥匙串和第三方账户不搬动。
- 当前图标只是 TC 字样占位，网页侧边栏仍有 M 占位；请制作完整品牌资源和适合 macOS 的单色菜单栏图标。

## 实施及验收方式

先独立检查现有实现，选择合理的视觉方向后直接推进。可以重构前端或为必要交互补齐接口，普通设计问题自行决定；不要为“看起来完整”编造余额、任务、终端或审核结果。沿用轻量界面和原生能力，依赖变化说明理由。

本轮已有 23 项桌面／控制器回归通过，Swift 与桌面 Python 类型检查通过；实际原生夹具验证了标题、完整工作台、关闭后恢复、忙碌退出提示和空闲退出时窗口／后台均结束。真实冻结后端另验了最小 PATH 冷启动、同 PID 复用、安全退出和重复退出不重启，未调用模型。CUA 无法取得 Dock／SystemUIServer 的截图，菜单栏图标位置、菜单点击与 Dock 视觉仍需原生检查；不能声称已全覆盖。

按修改范围运行有意义的检查，使用临时项目、模拟数据和隔离端口；不要反复运行无关的大回归拖延实现。原生窗口与浏览器的实际渲染、浅深色、不同窗口尺寸、长名称、空数据、加载失败、键盘和菜单操作都要检查，保存本机截图和简短回执。App 当前仅本机 Apple Silicon 构建、本地签名，未 Developer ID 公证；旧版自管安装源码尚无自动升级器，不能靠覆盖其配置实现更新。

交付可运行应用、对应源码和更新的文档／功能清单。GitHub 已是公开目标：每次发布都检查完整新增内容和历史，不上传账户、密钥、日志、会话、运行数据、绝对本机路径或开发交接。提交、推送与部署按当次用户授权处理；不要将本交接理解为以后无限发布授权。
