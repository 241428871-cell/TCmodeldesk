# 消息流图与 CLI 检查器

补充设计 0.1　2026年10月22日

## 采用的方案

在项目主区域增加“消息流”页签，保留最左侧项目树。借鉴 ComfyUI 的节点、端口、连线和属性检查方式，但不引入图像生成系统或第二套编排器。默认一张流图和一个右侧检查抽屉。普通使用不需要配置节点、写表达式或操作画布才能运行目标。[F1]

第一版使用 SVG 连线与原生 DOM 节点，无 WebGL、持续动画或重量级图编辑框架。提供由相同读模型生成的文本列表模式，适合小屏、远程桌面和较大任务。它不是另一套状态机。仅当实测布局瓶颈出现时，才评估可延迟加载的布局库。

流图展示系统已经观察到的事件，不参与主脑推理，不发模型请求，也不新增续接时钟。打开、展开和查看 CLI 均为观察行为；真实写入操作必须通过控制接口。

# 节点 连线与轻量布局

## 图上显示什么

项目内按主脑、执行者、人工待处理和外部工具分组。模型连接、已注册 CLI 会话和真实活动调用分别标记；尚未启动的连接不能显示成运行实例。节点摘要仅显示模型、任务、会话短标识、实际状态、最后事件时间与消息计数。

| 连线 | 表示的事实 | 默认行为 |
| 消息线 | 有已发出或已接收的真实消息记录 | 实线 箭头 点击查看对应事件 |
| 依赖线 | 计划中的任务依赖 | 默认隐藏 打开依赖层后用虚线 |
| 未知或缺口 | 已知存在观测缺口 | 显示缺口提示 不补画成功传递 |

消息图允许反馈和循环；任务依赖图仍按计划合同校验无环。两者不能复用同一种语义。不同事件只有在明确的 correlation_id、父调用或派发收据能够证明关系时才连线，不能按相近时间猜测因果。

同一消息的发送、接收与增量块不重复计为多条消息。折叠项目组时显示汇总数量，展开才请求细节。拖动节点只改变本机布局；手工连线不能直接改运行计划，计划变化仍由主脑通过版本化补丁提交。

默认不显示动态跑线、迷你地图或每个 token。保留缩放、适合窗口、定位活动节点、错误筛选和清晰的状态文字。暂停“跟随消息”仅停止画面追随，不暂停任何任务。

# 双击只读查看真实后端

单击节点选中并显示摘要；双击、Enter 或“查看后端”打开右侧检查抽屉。窄屏使用全宽检查面板，保留明确返回按钮。抽屉分为后端输出、消息、运行信息三个页签，默认打开后端输出。

| 后端能力 | 展示方式 | 必须标明 |
| 已托管 PTY | 原运行器复制的真实终端屏幕及有界滚动记录 | 只读镜像 实时或历史 更新时间 |
| 结构化 CLI | 原生事件和真实输出块 按需查看原始结构 | 原生事件视图 没有终端画面 |
| 已结束会话 | 已保存的原会话输出和结果引用 | 历史记录 不冒充仍在运行 |
| 失联或不支持观察 | 最近成功画面及原因 | 已过期 失联或未支持 不伪造空终端 |

Codex 使用精确 thread_id、turn_id 和原生事件。只读历史采用 thread/read、turns/items 读取等可用接口，不为查看记录执行 resume、turn/start 或新的 prompt。[F2]

Claude 读取原运行器已接收的流事件与会话输出。官方流会同时包含增量与完整块，归一化层需要避免把同一内容重复追加。没有被本工作台托管的任意终端，不假装可以自动镜像。[F3]

一个运行器拥有 PTY／stdout 的唯一读取端，再将事件复制给检查器。浏览器不直接成为第二个终端读取者。只读模式禁止发送键盘、粘贴、终端调整、快捷控制序列或隐藏输入；复制选中文字只作用于浏览器。

# 右键编辑与运行控制

节点右键与三点菜单等价，打开菜单本身没有副作用。可用项由当前后端能力和用户授权计算；不支持项置灰并解释原因，不能静默映射成其他操作。

| 菜单项 | 控制合同 |
| 查看后端／消息／运行信息 | 只读 不启动或恢复 CLI |
| 编辑运行参数 | effort fast 压缩窗口 模型及权限 显示请求值与实际生效值 |
| 修改默认配置 | 默认作用于新任务 形成项目配置新版本 |
| 应用到当前会话 | 仅按原生支持的下一回合或热更新能力执行 不改写在途快照 |
| 暂停新派发 | 改变控制意图 不谎称原生进程已经暂停 |
| 中断当前回合／停止目标 | 走原控制通道 绑定当前会话及 epoch 记录真实结果 |
| 明确恢复 | 仅用于可恢复的原目标 不创建重复会话 |
| 复制诊断摘要 | 脱敏身份 参数版本和错误 不导出凭据 |

如需直接向 CLI 输入，使用独立的“接管交互”操作，而不是打开抽屉便获得写入能力。接管必须先取得单一输入所有权，明确暂停主脑的自动输入；释放后按原会话身份交回。当前版本未实现接管时，该项不可用，不能用 shell 输入框冒充受控接管。

改变模型、auto 权限或压缩窗口，需要显示是下次会话、下一回合还是当前生效。原生拒绝或不支持保留原配置并报告，不能为了操作成功降级成 bypass。视图位置与折叠状态可以随时编辑，不影响任何模型与执行授权。

# 数据接口 性能与记录边界

## 共用现有事件而非再造日志平台

TraceEvent 包含 event_id、项目、目标、单调聚合序号、原生事件引用、来源／目标会话和 correlation_id。图快照只包含摘要与内容引用，完整 CLI 输出按明确会话分页读取。任务、账户和其他项目原始聊天不装入图节点。

采用 snapshot + after_seq 增量读取；原生输出块经批量合并后更新 UI。断线后按游标补读，保留序号缺口；缺口不能写成成功传递。服务端对每项目维护有界观察窗口，历史细节从原记录读取。视图限额只限制渲染，不能删除收据、审计事件或原生结果。

建议初始预算为每图默认最多 100 个可见节点、200 条汇总边，刷新合并 250ms。以上是待测的产品起始值，不是性能测试结论。超限显示可展开汇总及省略数量；不静默丢失错误。后台页暂停渲染，关闭抽屉即退订细节，避免为不可见终端不断布局。

| 接口 | 行为 |
| GET /v2/projects/{id}/flow | 有界只读快照 明确最新序号与省略数量 |
| GET /v2/projects/{id}/flow/events?after={seq} | 增量消息与状态 游标恢复 |
| GET /v2/sessions/{id}/view | 受信会话检查器 输出模式 能力和新鲜度 |
| GET /v2/sessions/{id}/output?after={cursor} | 当前会话有界输出 不执行 resume |
| POST /v2/sessions/{id}/commands | 结构化控制 request_id expected_revision epoch |

终端输出和模型消息按不可信文本处理，不执行 HTML、链接脚本或 OSC 剪贴板指令。内容引用为不透明 ID，不能接受浏览器传入任意文件路径。每次读取都核对项目与会话归属，状态过期不扩大观察或控制权限。

# 接入顺序与验收

先实现事件归一化与只读流图投影，再把原生运行器的真实事件接入。CLI 检查器复用同一会话的事件和 PTY 镜像，控制菜单复用现有命令接口。最后才加入视图布局、折叠、定位与文本模式；不建立独立模型代理或调度器。

必须验证以下情况：重复发送／接收不双计、消息循环可显示、依赖边不能冒充实际消息、项目切换无串流、查看历史不恢复会话、只读键盘不进入后端、旧节点不能控制新会话、失联不显示假运行、暂停画面不暂停任务，以及未支持参数不能显示已生效。

性能验收使用带长消息、持续输出和折叠组的真实浏览器进程，记录闲置与输出时的内存、CPU、更新耗时和节点数量。文本模式与图形模式使用同一事件快照，至少核对浅深色、键盘和小屏。基准测试不启动真实模型；原生端到端验收另按有效账户与费用授权执行。

这项功能并入当前 TCAUTO 重构目标，沿用原 30 分钟续接入口。仅有投影测试或设计图不代表真实 CLI 已接线；没有完成后端绑定与界面交互前，保持未验收状态。
