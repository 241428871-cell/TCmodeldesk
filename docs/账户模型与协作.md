# 账户、模型与多 agent 协作（0.3.3）

0.3.6 的“固定目标与准则”支持部分填写：目标名称、期望结果、固定验收准则至少填写一项。保存只记录输入，不调用模型；首次点击“交给 AI 拆分”时，由项目决策主脑依据已有输入和项目事实补充其余内容，并独立显示为“AI 补充内容”。主脑不能改写人类已填的名称和期望结果，人类固定准则继续单独保留。收尾义务可选；主脑补充的必要事项进入同一持久待办清单，重新规划不会删除未完成事项，须有核验证据才可完成。无法判断的目标意图或额外授权才提交人工审核。

文件范围、费用、审核策略与续跑周期仍由已有设置和明确授权决定。指定文件列表为空仍不允许修改；续跑周期留空使用表单原有 30 分钟默认值。旧目标、旧主脑动作与已保存的动作批次保持兼容，不因新功能重新授权或强制生成另一套要求。

0.3.5 新增“项目 → 设置 → 将当前配置存为新项目默认”。它保存当前项目已保存的决策／执行模型引用、默认角色、启用状态、思考强度、fast、上下文／压缩、分工提示、模型实例限制和项目并发。以后新建项目自动沿用；现有项目不会重置，目标、记录、费用授权和账户密钥不进入模板。模板位于本机数据目录的 `.local-worker/project-defaults.json`，不发布、不嵌入通用安装包。删除或更换被引用模型后须重新保存模板，不会换到其他模型。全局执行端、原生技能与协作策略继续使用本安装原有设置。

0.3.4 修正：项目模型接口此前缺少思考能力字段，导致通过 DSH 执行的 DeepSeek API 模型在运行设置中只显示默认等级，点击读取也无变化。项目接口现携带同一份只读能力信息，原生 DSH 按精确账户／模型路由读取缓存；查询不启动模型、不改写配置。API 模型显示能力说明来源。61 项相关检查与隔离浏览器选择、保存、再次读取场景通过；此修正不更换账户或模型，不改变已有思考设置。

## 操作顺序

1. 打开“模型库 → 管理 API 账户与密钥”。账户只保存名称、服务商、接口和密钥，不需要模型 ID，也不会创建模型或产生推理费用。
2. 添加 API / 本地模型时选择已有账户，再填写或读取模型 ID。一个账户可供多个模型引用；模型名称、声明容量与单价属于模型。
3. 将模型加入项目的决策／执行分类。右键“运行设置”配置该项目的思考强度、上下文预算、自动压缩、分工提示与执行实例上限；Codex 另有 fast。保存只影响新任务／新会话。
4. 在“设置 → 多 agent 分工策略”写总提示，以及 Claude、DSH、Codex 的分工偏好。主脑的真实规划上下文会收到这些提示和项目模型提示；执行任务也会收到对应的项目分工提示。

原有模型密钥只会作为“原有账户”显示，读取不改写文件。明确保存／换绑时在同一模型库原子写入中保留原安全存储引用，避免重新输入密钥。账户仍被模型引用时不能移除。密钥不会出现在模型公共响应、源码包或 GitHub 中。

## DSH 模型与官方账户

“读取 DSH 模型”从所选 DSH CLI 的官方 LLM 服务读取模型与精确能力；登录账户路由 `deepseek-account` 与 API Key 路由 `deepseek-official` 分开标注、分开选择，执行时不替换认证来源。当前支持这两条官方原生路由；其他服务商通过 API 账户添加并由 DSH 执行。

“账户与额度 → 从 DSH CLI 读取官方账户”主动调用官方 `accountController.getState/getBalance`。它不依赖宿主插件向某个旧工作台持续推送；宿主插件推送仍可使用。DSH 登录钱包和独立 DeepSeek API Key 的 `/user/balance` 保持独立，查询余额不等于费用授权。

DSH 默认继续使用桌面应用提供的后台 CLI，不会打开 DSH 窗口。独立官方 npm CLI 安装完成后，可在“执行端与 CLI”选择“独立 CLI”并保存；缺失来源不会静默回退。安装本身不切换已有来源、不改登录账户。

本轮机器上的独立 CLI 为 `@deepseek-ai/dsh` 0.2.1-rc.3，另有独立 Node 22。通用位置：`~/.local/share/tcmodeldesk/dsh-cli`、`~/.local/share/tcmodeldesk/node22`；`~/.local/bin/dsh-standalone --version` 可单独运行。原来的桌面 `dsh` 入口保留。版本检查使用官方 npm 目录，不把较旧 latest 候选当作可升级版本；仅已识别的本产品独立安装前缀支持面板更新。

## 运行设置实际如何生效

- Codex／Claude 参数继续进入其原生 CLI 参数。
- DSH API 模型的项目思考设置进入工作台请求处理；原生模型进入对应官方 DSH provider 的 reasoning 配置。
- DSH 上下文预算进入运行时精确模型覆盖，压缩阈值进入官方 `compaction-basic` 策略。阈值还受真实窗口与预留输出限制，属于触发上限；原生压缩可能调用模型并产生费用，余额／模型扫描不会。
- 已有任务的运行、实例容量与授权快照保留。恢复不继承新配置，避免偷偷升级权限或更换认证来源。

原生 DSH 账户内部的费用和请求次数不可由工作台精确计量。使用它仍需现有付费授权，并显式关闭无法保证的金额与请求次数硬上限；新版本不自动修改这些设置，实际成本显示未知。

## 多实例与分工

新安装默认开启多 agent 协作，费用授权仍默认关闭。旧配置中的显式关闭、暂停或 STOP 不会被版本默认值恢复。打开界面、导入模块、列工具和读取模型列表不启动模型任务。

新增项目默认工作并发为 8，新执行实例的账户与模型容量默认也为 8；三项均可配置为 1–64。已有明确保存的项目／账户／模型容量保留。同一个模型配置可以产生多个独立任务实例，不需要重复添加模型。项目容量、跨项目账户容量、项目模型容量与文件冲突共同决定是否启动；上限不是服务商对并行能力的保证。

并行执行使用现有持久租约；旧租约较小的限制在释放前继续有效，崩溃／取消后仍需子进程静止与写回核对。每个目标的主脑轮次保持唯一正式入口；上述实例池约束的是执行任务，不把多个主脑同时推进同一目标当作并发加速。

分工文本是人类偏好，不是未经测量的模型优劣结论。主脑可按实际任务与结果调整；需要另一模型参与审查时可建立独立只读审查阶段，最终主脑仍须核对成果和证据。

## 原生 skills 与 TCAUTO

Codex、Claude 保留原生 CLI 的用户环境与技能发现，Claude 的 cswap 账户切换不被复制或替换。DSH 的隔离执行 home 显式接入原用户的原生技能目录，避免隔离 home 导致看不到已安装的技能。

默认采用“优先使用原生 TCAUTO skill”：只提示实例读取自身实际安装的 `tcauto`，不重复嵌入整套工程模板，也不另建续接时钟。未找到技能时必须如实记录未加载，不能声称已生效；文件存在或提示已发送不等于模型实际调用技能。“内嵌已选择的工程习惯”仍可明确选择。人类保存的自定义要求与工作台的授权、项目隔离、暂停／停止和独立验收约束继续有效。
