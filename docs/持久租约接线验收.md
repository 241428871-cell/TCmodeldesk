# 持久租约接入生产执行链

日期：2026-10-23。唯一实施目录 `native-langgraph`，分支 `feat/claude-taskgraph-purge`。代码已接入真实执行入口；没有提交、推送、部署，没有修改原 AAD、8765、真实账户、费用授权或全局规则，也没有调用真实模型。

## 当前执行链

1. 公共 `execute_task` 先取得本地等待票据，再通过 `lease_runtime` 在安装共享库中取得项目、执行账户桶及文件租约。跨进程等待保留 STOP 检查和面板等待原因，不另建时钟。
2. 存储路径固定为当前安装的 `.local-worker/resource-leases.db`。数据库应用标识与独立 identity 标记绑定；丢库、替换库、未知库、链接及坏回执不能被当作空库重新准入。读取状态不创建数据库，运行文件由现有 `.db*` 忽略规则排除。
3. 原目标授权、费用及模型范围检查保持原位。Popen 前提交 armed，原命令通过 `lease_runner.py` 引导；工作器在执行原脚本前用自己的真实 PID／出生时间登记 started。登记不依赖父进程成功保存启动回执。
4. Claude/Codex、DSH/Pi、WorkBuddy、直接咨询与 Aider 的既有子工作器入口核对实际资源、token 和当前 launcher 身份。新版协议任务缺 token 不能降级为历史任务；无协议的历史直接入口保留其原保护边界。
5. POSIX 下受管嵌套 CLI 保留工作器的会话。释放必须核对确切 launcher 已退出，并扫描该会话中是否还有活进程，包含被重新挂到其他父进程的后台子进程。任何不可读状态均不作为退出证据。取消嵌套 CLI 时终止该任务会话内的子进程，保留工作器记录结果。
6. 回调结束后若资源仍未静止，任务进入原待核对列表，租约保留；取消标记仍优先。启动时也核对“任务写了完成、租约尚未释放”的情况。释放之后才发送完成事件；阶段同步、独立验收、永久删除和主脑移交另有持久租约保护，不能仅信 completed／cancelled 标签。

首次建库使用 `initializing:<identity> → ready:<identity>` 两阶段标记。完整 SQLite 先在同目录临时库中建立、同步并原子发布，随后才发布 ready 标记；任一阶段都同步父目录。中断发生在 initializing 标记之后、数据库发布之前时，下一次事务可重建尚未对外使用的临时库；中断发生在完整数据库发布之后、ready 标记之前时，下一次事务核对 application id 与 identity 后只补 ready 发布。旧版 32 位裸 identity 按 ready 兼容读取。ready／旧版标记对应的数据库一旦丢失仍拒绝重建；只读入口遇到 initializing 状态也拒绝把它显示为空库。

同一安装的 Codex MCP、DSH loopback 和多工作台实例共用这条链。账户桶是执行任务的保守归类，不是服务商核实的账户身份；没有改变现有费用授权。

## 文件恢复接管

原 recover 入口继续核对当前授权、独立验收状态、原运行及回执，然后在同一资源事务内释放可证明静止的旧代次并取得恢复代次。若竞争资源不可得，整个交换回滚；没有先解锁、随后无锁写回的窗口。

恢复进程在取得新代次后、保存 token 前崩溃，下一次显式恢复可凭确切 owner 退出回收其 reserved 记录。armed 缺 launcher 的未知启动仍不能这样回收。旧 token、未知进程、当前存活子进程、字段不匹配和存储损坏均拒绝。

恢复只应用已保存且可核对的候选，不重发模型、不重新运行测试、不改变原费用计数。完成后释放恢复租约并同步原阶段，继续等待独立验收。

## 实际进程验收

测试运行生产父执行器、生产 lease_runner 和原恢复入口；模型 CLI 被隔离项目内的 Python 工作器替代，未使用真实账号。

- 工作器必须先证明自己的持久身份才能写测试标记；正常退出后租约 released。
- 工作器结束但后台子进程仍存活时，原任务待核对，跨进程资源保持，恢复接管拒绝。
- 嵌套子进程取消后，工作器仍可保存取消结果，确认会话静止后释放。
- 父进程启动回执写入失败时，子工作器仍能自行登记；保存的文件成果经原恢复入口完成，未发生第二次 Popen。
- 独立控制器进程真实退出，工作器继续存活；另一个控制器无法取得相同资源，待工作器停止后才可接管。身份采用实际 PID 和出生时间。
- 坏库／丢库、链接、UNKNOWN、reserved 原任务续接、恢复 token 落盘间隙、竞争接管回滚、验收／删除／阶段／移交保护均有回归。

## 明确限制和未完成义务

- 共享范围是同一个安装资源库。不同安装或不同机器没有统一资源域，不能称分布式协调完成。
- POSIX 证明覆盖受管会话和已观察后代。macOS 另使用 kqueue fork 通知，把通知时间窗内被 PID 1 重新托管的同用户存活进程保存为疑似逃逸并阻止释放。它不是阻止任意程序 setsid 的内核沙箱，也不是 EndpointSecurity 级完整谱系；外部 GUI／远程执行器不因此获得 OS 隔离。
- 用户于 2026-10-23 明确取消 Windows 适配；Job Object、Windows 安装与原生验收均不再安排，也不作为交付阻塞项。保留既有兼容代码；containment=none 仍不自动释放 started，不将未支持行为伪装为成功。
- 已完成 POSIX 文件与父目录同步、首次建库两阶段独立进程退出恢复、多文件写回中途 `SIGKILL` 后的新进程接管，以及删除日志提交后 `SIGKILL` 再由新进程清理 checkpoint／暂存目录。按用户确定的范围，不安排真实拔电、文件系统挂载参数或硬件缓存级验证；这些不再作为交付阻塞项。恶意外部篡改、跨进程公平调度和历史无协议入口迁移仍未完成。
- 真实 Claude/Codex 与外部宿主、GUI、账户额度、macOS 安装与发布验收继续保留。未获授权的真实模型或部署不执行；SOURCE-MANIFEST 待发布授权时处理。

开发已改由 Goal 驱动，aad 与 Claude 旧时钟保持暂停。下一阶段是消息流控制闭环、macOS 安装迁移、逐次运行证据与其余原生验收；不能宣布完整软件已交付。

## macOS fork 事件与重新托管候选围栏（2026年10月23日）

- lease_runner 在执行原工作器脚本前同步注册 Darwin kqueue `NOTE_FORK`；轮询继续负责确定后代身份。若发生 fork，同时扫描短时间窗内由 PID 1 重新托管的同用户存活进程，只保存 PID／出生时间，不读取命令行、环境、账户或文件。
- 这些进程标为 `suspected_orphans`，参与 quiet／release／takeover；存活时拒绝自动释放。由于 kqueue 不返回子 PID，候选不是足够的停止授权，原停止动作不会向它发信号，避免误杀并发无关进程。任务详情只读证据显示确定后代数、疑似数、guard 类型和观察状态。
- 真实生产 lease_runner 用例在0.2秒采样间隙内执行双重 fork：短暂父进程退出，孙进程 `setsid` 并重新托管。候选被保存，原租约拒绝释放；该进程退出后同一租约可释放。普通无子进程完成、受控短命子进程停止、控制器退出、取消与文件写回恢复保持原行为。
- 受影响租约／停止／恢复／只读证据专项34项通过（`-W error`）；窄文件 Ruff 和 `git diff --check` 通过。沙箱内 macOS 禁止 psutil 读取进程表，初次运行正确变成 UNKNOWN；随后仅对隔离本地进程测试开放进程表权限，未修改断言掩盖环境差异。未重跑全量。
- 这解决了已验证的“短暂父进程遗弃一个仍存活后代”窗口，但不是完整内核谱系：kqueue 事件本身没有子 PID，时间窗并发进程可能被保守围栏；不同安装、远程执行和恶意程序绕过仍不在证明范围。未提交、推送、部署或改动原服务／账户／费用／全局规则。
