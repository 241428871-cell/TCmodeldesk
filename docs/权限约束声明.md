# 权限约束声明与验证范围

2026-10-23。此能力报告已有适配器的约束，不修改权限、账户、全局规则或运行命令。

模型详情页“权限约束”按当前项目的角色与执行器显示。决策角色按模型提供商识别原生主脑；执行角色按原有执行端解析结果识别。缺少声明或未知角色显示“未支持”。公共 `execution_agents` 和项目 binding 的 `enforcement` 使用同一个核心定义。

| 适配器与角色 | enforcement_scope | 依据与限制 |
| --- | --- | --- |
| Codex 原生主脑／执行器 | native_sandbox | `native_commands.py`、`cli_worker.py` 配置 read-only／workspace-write。auto 审批可能扩大单次访问；不是运行时沙箱证明，项目内记录目录仍有缺口。 |
| Claude 原生主脑（macOS） | native_sandbox | 原生 `safe-mode` 本身不限制路径；生产启动现额外继承 Seatbelt 写围栏，只允许稳定隔离副本、专用临时区及 Claude 会话状态写入。项目外绝对路径由 OS 拒绝。 |
| Claude 执行器（macOS） | native_sandbox | 临时副本与所有子进程继承同一 Seatbelt 写围栏，随后仍只按声明文件、测试和回执写回。边界不限制读取，Claude 会话状态仍可写。 |
| Claude（非 macOS） | controlled_tools／dispatch_only | 保留原 `safe-mode`、工具权限、隔离副本和受检写回，但不声明 OS 写入沙箱。Windows 已不在当前交付范围。 |
| DSH、Pi、WorkBuddy 执行器 | controlled_tools | 各 worker 及 agent-runtime 里的工具参数／记录保护与原回执核对。任意子进程并不因此得到 OS 级隔离；具体访问模式仍取任务快照。 |
| direct、aider | dispatch_only | 沿用任务准入／验收，不声明额外工具或沙箱约束。 |
| 其他原生主脑、未知适配器或角色 | unsupported | 不从执行器支持推导主脑支持，也不从显示名称猜测。 |

这些 scope 表示机制，不是安全等级排序。声明固定为 `basis=adapter_declaration`、`runtime_verified=false`，类型拒绝将它伪装为已验证运行。运行器已具备的有效模式／保护回执验证保持原样；后续若展示逐次运行证明，必须从该任务的实际回执读取并单独标识，不能依赖这里的声明。

2026-10-23 的真实原生探针首先证明 Claude `--safe-mode --permission-mode auto` 会接受项目外绝对路径写入，因此不能把 `safe-mode` 名称当作沙箱。接入 Seatbelt 后用同一 `claude-haiku-5-5`、同一工作副本和同一外部标记路径复验：副本内写入成功，外部写入返回 `EPERM` 且文件不存在。Codex `gpt-6-luna` 的 production `workspace-write` 在同一外部路径上由 Seatbelt 拒绝。两者都没有读取外部文件；临时标记与会话探针随后清理。
