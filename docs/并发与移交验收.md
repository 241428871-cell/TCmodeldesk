# 并发租约与主脑移交验收

日期：2026-10-23。实施目录：`.omo/worktrees/native-langgraph`，分支 `feat/claude-taskgraph-purge`。仅离线验证和临时浏览器夹具，未提交、发布或启动真实模型。

## 已落地

- 项目执行并发默认 1，可显式设置 1–4。公共执行入口申请项目、账户桶与写文件租约；项目设置显示当前项目等待原因，保留未保存草稿。
- 重叠写文件、目录独占、嵌套项目与符号链接别名互斥。取消／STOP 退出等待；租约配置失效不能绕过准入。原队列活 owner 不因等待而被重复补投。
- 暂停目标可显式移交到本项目启用的 Claude/Codex 决策模型。移交保持暂停，不调用模型，不改变固定准则、计划、周期或义务。
- 原项目锁与事务同时保存双代次和回执。旧原生身份保存在时钟的 owner_history，新会话置空。重复请求返回原回执，过期代次与冲突请求拒绝。

## 接口

原人类治理接口 `POST /api/governance/goals/{goal_id}/control`，沿用会话鉴权及浏览器项目绑定。请求示例为结构说明，不能直接用于真实目标：

```json
{
  "action": "handoff",
  "project": "<当前项目的规范绝对路径>",
  "request_id": "<本次移交唯一标识，重试保持不变>",
  "model_id": "<项目决策模型标识>",
  "expected_owner_epoch": 0,
  "expected_authority_epoch": 3
}
```

目标须活动且处于 USER_PAUSE，无保持、无 active_intent_id，也无 claimed／started／unknown／revoked 轮次记录；执行阶段与队列必须已结束或已阻止。移交成功返回原／新身份代次回执。恢复续跑使用既有显式控制，不由移交隐式执行。

## 06:00 UTC 续接：资源身份与候选写回

先复现三个缺陷，再修复并回归：

1. 等待租约后模型提供商改变，旧代码仍启动工作器。父执行器现比较当前资源请求与已取得租约，子工作器再对其实际模型、规范路径与并发上限复核原快照。连接桶、文件集合、别名或上限改变均拒绝；无凭据快照不证明跨进程锁持有。改变同一桶内的模型／密钥不新增额度，不取消原费用围栏。
2. 租约等待取消后，若当前授权又允许，旧代码可进入无租约执行。取消路径现显式携带准入失败，不能因后续授权状态变化而绕过租约；真正的任务取消仍保留原取消结果。
3. CLI 副本生成结果期间原文件被人修改，旧 copy2 会静默覆盖。共享核心先核对复制基线，再保留候选和清单，整批预检通过后才写回；冲突时原修改保留。未修改候选不还原外部编辑，精确已应用结果可幂等跳过，丢失候选或候选被修改均阻止应用。逐文件替换沿用原目标权限围栏，已应用文件即时登记。

候选位置：原任务目录的 `native-cli/<capture_id>/proposed-files/`，清单 `native-cli/<capture_id>/writeback-plan.json`；task.json 记录 writeback_capture_id、writeback_state 与冲突名。这里保存的是私有运行成果，不应发布到源码仓库。冲突不自动重发提示或替人解决语义冲突；原任务失败／恢复和独立验收继续承担后续处理。

验证覆盖：父启动点拒绝；六种执行路径对子工作器快照复核（Pi 复用 DSH）；坏快照不能降级为历史路径；取消与 STOP；文件新建／修改／删除／权限变化；整批末文件冲突不先写前文件；候选被修改、复制漂移与链接拒绝；两个 Claude/Codex Python 替身同时从旧副本修改不同文件，最终两个结果均保留。核心新增 9 项，工作台新增 19 项。
