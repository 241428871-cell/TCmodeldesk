# Model Desk 完整软件设计

版本 0.2　2026年10月22日（0.2 增加多 agent 协作章节、实现状态对照，并更正 0.1 中已被生产 TaskGraph 与完整删除取代的“未完成”表述）

## CLI 与账户管理决策（2026-10-23 更新）

- 采用外部 CLI 适配器。AAD 包含编排、状态与适配代码，不把 Codex／Claude／DSH 或账户管理器复制进软件发行包。
- **Codex 与 DSH 默认使用桌面版内置后端**。在共享的‘执行端与 CLI’中可显式切换为已安装的独立 CLI，选择持久保存；主脑、执行器、目录、额度和更新使用同一解析结果。所选来源缺失时显示不可用，不自动换来源。独立模式排除指向应用包的符号链接。Codex 独立绝对路径使用 `MODEL_DESK_CODEX_CLI`，桌面路径可用 `MODEL_DESK_CODEX_DESKTOP`；DSH 独立入口使用 `MODEL_DESK_DSH_CLI`。默认不复制或另装第三方运行时。
- **Claude 继续使用用户现有 CLI 和 cswap**。不另装内置副本，不复制凭据，不接管自定义 cswap，不固定 Claude 版本符号链接的目标；新进程继承当前 CLI／登录环境。进行中的进程不会因外部账号切换自动迁移，账户快照需要按原接口刷新；本轮没有执行真实账号切换，不能宣称其原生人工验收完成。
- **DSH 两种来源均保持后台执行**，不唤醒桌面窗口。桌面模式使用应用内官方后台命令；独立模式使用所选 npm 包的版本、预设和指定 Node，不借用桌面包的能力证明。本机当前仅检测到桌面版，独立选项显示未安装；独立模式有隔离夹具证据，未声称完成本机独立 DSH 推理验收。
- **Pi 暂不适配**：用户不用，移出当前支持扩展、安装与验收义务，不再作为交付阻塞；既有代码与历史配置只保留兼容，不擅自删除记录或重设模型默认值。
- 独立 Codex 的更新使用其原生 `codex update`，Claude 继续用 `claude update`；版本、签名、来源、过期状态及全局任务／主脑更新门禁保持分离。官方独立包布局识别成功才给 Codex 提供原生更新入口，未知来源不自动更新。

## 设计决策

重构为以项目文件夹为入口的本地多智能体工作台。用户给目标、准则、资源和决策边界；Claude CLI 或 Codex CLI 担任主脑，自主调查、拆分、派发、整改和判断交付。主脑使用原生 auto 权限，不能把 auto 偷换成 bypassPermissions、yolo 或无条件允许。LangGraph 是状态编排内核，不额外加入一个 API 规划模型取代原生主脑。

保留现有 AAD 中有效的模型连接、账户读取、任务记录、费用授权与独立验收。项目侧栏、动态治理是另一会话正在维护的成果，应按接口和测试迁移，不能覆盖其未提交文件，也不能把两个工作区的代码直接混装。完整软件的验收对象包括实际原生会话与界面，不以设计、配置开关或离线测试代替。

第一版采用 Python 控制服务、LangGraph、SQLite、本地浏览器界面和原生 CLI 运行器。保持现有前端技术，先完成信息结构和控制闭环；不同时改成 React、增加 Electron、叠加 Temporal 或替换所有执行端。未来出现多主机和高可用要求时，再将持久层迁移至 PostgreSQL，保持领域合同不变。[R1][R2]

## 当前基线的真实边界

原始上游公开 README 仍描述 Windows、串行队列及不完整的休眠恢复。本地 AAD 已有 Mac 和 Claude/Codex 执行适配，并出现账户、项目关联与侧栏新模块。二者不是同一源码快照。设计以本地已核对接口作为复用输入，以公开 main 为隔离实施基线。[R3][L1]

# 信息架构与页面布局

## 最左侧项目树

侧栏宽度默认 272px，可拖动，保存到本机界面偏好。桌面固定，窄屏变为可关闭抽屉。树从项目文件夹展开到角色，再到模型关联。这里的子文件夹是逻辑分类，不向磁盘创建“决策模型”或“执行模型”目录。

| 层级 | 显示内容 | 点击结果 |
| 项目 | 显示名 路径提示 活动数 异常数 | 项目总览 |
| 决策模型 | 默认主脑 会话数 | 当前项目决策配置 |
| 执行模型 | 可派发数 工作中数量 | 当前项目执行配置 |
| 模型关联 | 模型名 Provider 默认标记 状态 操作菜单 | 右侧模型检查器 |

项目选择只改变视图，不能改变活动任务的项目、账户或模型。项目 A 和 B 同时运行时，各自显示活动状态。重复添加同一规范化目录只选择原项目；目录不存在时显示失联，不替换成当前目录。路径别名与符号链接按规范化身份处理，展示原显示名。

## 主区域与右上角

主区域包含总览、目标与任务、原生会话、待处理、成果与验收、项目设置。连接库与账户位于全局工具入口，不再与项目同级含混命名。右上角提供工程习惯、全局连接、账户和应用设置。项目选择不清空编辑草稿，轮询不得覆盖未保存表单。决策模型的“启动中／已启动／待核对”来自持久主脑轮次的 claimed／started／unknown 回执；执行模型的“运行中”来自真实任务。已启用或 CLI 可用只显示“已就绪”，不能冒充已经启动。模型右键可按项目、模型 ID 和角色定位公共消息流中的真实会话，再使用该节点已有的只读输出、设置与目标／任务控制；找不到会话时明确提示，不制造占位实例。

账户摘要始终标注账户来源和更新时间。顶部只显示相关账户，完整账户详情在抽屉中。待处理数量可见，但无变化的同一阻断不重复弹窗或通知。界面遵循当前 DESIGN.md 的浅深色、系统字体、焦点和可读状态约定。[L2]

# 菜单与交互合同

## 项目操作

| 入口 | 行为与边界 |
| 添加项目 | 系统选择器或绝对路径 注册目录 不扫描秘密或派发模型 |
| 打开 | 选择项目总览 展示活动状态 |
| 重命名显示名 | 只改界面名称 不重命名磁盘目录 |
| 添加角色模型 | 选已有连接或显式读取原生目录 再建立项目关联 |
| 暂停项目派发 | 暂停新派发 明确列出活动任务处理范围 |
| 从侧栏移除 | 不删目录 历史或连接 活动目标仍能从活动列表打开 |

模型关联右键提供运行设置、设为角色默认、启用／停用、复制到另一角色、编辑共享连接、查看原生会话、移除项目关联。停用只影响新派发，不能隐式杀进程。编辑共享连接时先显示受影响项目，保存新版本；在途任务保留原绑定。删除连接先检查引用，提供停用或解除关联，不连带删除任务记录。

## 启动控制

“启动主脑”明确创建当前项目的原生会话；“连接已有会话”需要精确会话 ID 和项目证明；“继续目标”只用于已授权目标；“启用”仅表示候选可用。双击、回车与菜单按钮共享同一后端命令和幂等请求，不写三套控制逻辑。

右键菜单与可见的三点按钮等价，支持方向键、Home、End、Escape、焦点返回和外部点击关闭。模型正在运行时仍可打开参数表单，但保存默认只用于新任务。若选择应用到活动目标，应形成新策略版本并解释原生会话是否支持生效；不能显示保存成功后仍悄悄沿用旧值。

所有有副作用操作使用 POST 与 request_id。页面刷新、树展开、状态读取和模块导入都不得启动模型、后台服务或余额请求。

# 运行中消息合同

`/btw` 是目标旁路状态查询：只读取当前计划版本、执行和验收数量、待处理需求、阻碍与下一步，不改变授权代次、时钟、计划或队列，也不触发额外模型。工作台必须提供等效按钮；消息流节点以自身持久 `goal_id` 直达同一查询与需求表单，不能靠当前目标下拉框猜测归属。原生宿主通过模型可见 `goal_interact` 调用同一核心，项目身份来自受信启动上下文或当前线程。真实 Codex Luna 与 Claude Haiku 5.5 已在隔离项目验证工具调用、查询和需求写入；这不等于宿主二进制内建 slash-command 拦截。

普通运行中消息默认记录为增量需求；显式“方向调整”允许主脑重排后续阶段，但不取消原目标。暂停、STOP 和替换目标必须走独立控制动作。每条需求绑定项目、目标、单调版本、类型、创建时间、处理状态与实际处理轮次。在途轮次只核销自己快照中包含的最高版本；之后到达的需求保持 pending，并让下一安全轮次到期。方向调整持久化成功后还会写入旧主脑与受影响任务的停止信号：未启动队列原子退休，运行中的 CLI 子进程沿公共取消边界停止，阶段保存精确 superseded 标记；替代执行必须等待原进程退出证明与持久租约释放。中断回执分为 requested、not_needed 和 incomplete，失败不能伪装成“无需中断”，相同 request_id 可重放修复。生产动作链在计划、审核、问题、分支恢复、逐项派发、义务和完成候选的每个副作用边界重查所领取的版本；发现新版后将旧动作批持久结算为 `superseded`，停止后续效果且不核销需求。派发任务持久保存原轮次与需求版本；新版到达后，未启动队列按原 ticket 退休，已生成的 CLI 候选保留但不写入原项目，二者都形成可供下一轮整改的明确失败事实，而不是可误恢复的旧结果。阶段只接受精确最后任务的需求淘汰标记；下一轮计划不能改写已有任务历史，必须把旧阶段标成可查询的 superseded 历史并建立新 key 的后继阶段，后继任务经过相同生产队列并携带最新需求版本。此前已经原子提交的效果保留回执，下一轮从领域事实重建，不能伪装成整批回滚。主脑合并需求时保留不冲突准则、已完成成果和未完成义务，避免重复模型调用。

# 模型连接与目录

## 五类身份

ProviderAccount 是身份与额度来源；ModelConnection 是精确模型与传输方式；ProjectBinding 是项目角色关联；RuntimeProfile 是运行参数；NativeSession 是已经启动的真实会话。一个账户可以支持多个连接，同一连接可被多个项目引用，参数和启用状态仍按项目保存。

持久标识不使用模型显示名。模型主键包括 provider、account_ref、native_model_id 和 adapter_kind。CLI 模型与同名 API 模型不是同一连接，不能仅因名称相同合并费用、能力或会话。

## 原生目录发现

Codex 使用 app-server 的 model/list，处理游标、隐藏模型、默认 effort 和所支持 effort。模型选择器依据当前账户返回的目录，不写死“最新模型”。连接库保存目录读取时间、CLI 版本和能力摘要。新版本发现未知字段可以保留原始非秘密元数据，但不能据未知字段开启新能力。[R4]

已接入的原生 CLI 端点必须公开安装版本、可执行文件来源、官方软件包最新版本、检查时间语义和是否允许工作台更新。检查更新只读取官方版本元数据，不启动模型；结果在当前服务生命周期内保留并直接显示在执行端行，不能只弹出一次提示后消失。签名应用包内的 DSH／Codex 由宿主应用更新，工作台不得改写；独立 Claude CLI 只调用官方 `claude update`。真正执行更新前必须证明全局执行任务和原生主脑轮次均为空，任一项目状态不可读时 fail closed；用户仍需确认没有工作台以外终端正在使用同一 CLI。

Claude 复用本地 NativeMetadata 的控制接口。list_models 与 get_usage 在目前实现中带版本依赖，必须标为实验接口并固定契约测试；失败时显示未支持、过期缓存或手动输入，不伪造可用模型列表。手动输入的精确模型标识可以保存，但直到原生启动成功前不能称为已验证。[L3]

元数据读取运行在无项目内容的临时目录，不发送生成提示、关闭用户 hooks、禁止加载项目 MCP，并在完成或失败后回收进程。必须有进程数、输出大小和控制请求超时上限。读取目录不是推理验收；可见模型仍可能因账户策略不可调用。

API 模型目录通过各连接支持的官方接口读取；兼容服务不能假定支持 OpenAI 全部方法。内网地址与本地服务需按连接明示，不把 DeepSeek 官方 Key 发送到任意兼容 URL。

# 额度 余额与费用

## 统一展示模型

QuotaSnapshot 保存 account_id、source、observed_at、state、windows、balance 和 stale。未知是空值与原因，不能转换成零。刷新失败保留上一次成功数据及其时间，明确标记过期。账户级数据按身份去重，多个项目引用不会获得多份额度。

Claude 展示服务端确实返回的订阅窗口，例如短窗口、周窗口和模型专属窗口。用量比例、重置时刻、来源和可用性分别保存。没有稳定读取接口时明确不可读取，不能从 token 数推算剩余额度，也不能将会话估算成本当作订阅账单。[L3]

Codex 读取 account/rateLimits/read；优先使用 rateLimitsByLimitId，兼容单桶旧字段。usedPercent 表示已用，剩余由 100 减已用并限幅；空字段不等于零。API Key 模式与 ChatGPT 订阅模式分开展示。[R4]

DeepSeek 复用现有官方 GET /user/balance 适配，显示各币种的总余额、赠送与充值组成，以及账户是否可用。只接受已确认的官方连接，密钥留在既有凭据存储中。第三方兼容服务不复用官方余额。[R5][L4]

## 刷新与预算

普通轮询只读缓存。首次进入账户抽屉可提示刷新，用户点击才查询；允许用户另行开启账户观察，采用 TTL、单账户合并请求、限流和退避。账户刷新不发生成任务，不自动兑换重置、购买额度或变更登录。

主状态刷新按活动执行与页面可见性自适应：隐藏页不保留定时器，无运行任务且长期无变化时降低频率。治理快照遍历目标、阶段、时钟和人工事项，需独立节流；请求在途期间发生的状态提示合并为一次补读，不能直接丢弃。显式保存、插入需求、回答审核、暂停／停止和移交后的读取不受节流。项目切换后旧项目响应不得渲染。消息流拓扑只在弹窗打开时读取；原生 CLI 输出只在用户实际展开后读取有界尾部，不随整页常规轮询加载。

项目预算、调用授权、账户余额和供应商实际账单各有来源。预算在派发时原子预留，结算时释放或转实耗；金额未知时保持未知并沿用现有费用授权规则。余额下降可能来自其他应用，不全计入当前项目。低额度可使任务进入账户资源守卫，但不能擅换账户、模型或 API。[L4]

# 运行参数与默认值

| 参数 | 新关联默认 | 生效要求 |
| 原生权限 | Claude auto Codex 原生自动审批 | 必须能力探测 不支持就显示阻断 |
| 决策模型 | 用户选择的角色默认项 | 不擅自替换为最新或其他模型 |
| Effort | 原生推荐值 无推荐时 medium | 只能选当前模型支持的值 |
| Codex fast | 关闭 | 账户 模型与 CLI 能力均支持后才允许启用 |
| 上下文窗口 | 继承原生模型 | 无可靠能力值时允许手动覆盖并标注 |
| Autocompact | 原生自动 | 可手动窗口 旧 160k 配置保持而不静默迁移 |
| 工作并发 | 默认 1 可显式设为 2 或更高 | 仍受预算 文件冲突和资源租约限制 |
| 续接周期 | 30 分钟 | 自动只可退避增加 用户明确变更除外 |

这里改进了旧版固定 200k／160k 的新建默认值：用户可以保留旧设置，新建关联优先继承 CLI 的模型原生窗口。手动压缩值与实际模型上限核对，表单显示请求值、配置值和实际生效值，禁止把保存成功解释为 CLI 已采用。[L1][R6]

Claude --autocompact 表示窗口配置，并受原生缓冲与模型上限影响，不承诺精确在该 token 数触发。Codex 使用其实际支持的上下文和压缩配置；fast 是服务层能力，不能只凭模型名判断或仅把一个布尔值写进项目配置。[R6][R7]

参数解析使用白名单，不接受任意 CLI flags 或 shell 片段。配置分为全局默认、项目角色默认、模型关联覆盖和目标快照。旧任务与续接保持原运行快照；当前停止、撤权和预算收紧仍立即影响受控入口。原生会话不能热应用的参数在 UI 显示“下次会话生效”。

# 原生主脑与执行端

## 原生主脑合同

NativeBrainAdapter 提供 capabilities、start、resume、observe、interrupt、reconcile。每个目标有一个当前主脑所有者，可选择 Claude 或 Codex。它们可以分别控制不同目标，不能同时控制同一目标。移交必须更新 owner_epoch，核对原会话后再续接。

Codex 优先使用正式 app-server 事件与精确 thread_id／turn_id；Claude 使用正式控制与流事件和精确 session_id。若当前版本不能通过程序接口提供原生 auto，允许经已核对的 CLI 启动模式接入；不能通过无条件批准所有原生请求来模拟 auto。[R4][R8]

原生主脑读取目标和证据，通过受控工具提交计划和派发指令。主脑保留原生文件、终端和推理能力；控制服务管理项目归属、记录、预算、会话身份与恢复。模型正文不能伪造 trusted_project_id、账户或执行身份。

## 执行端复用

Pi、DSH、WorkBuddy 和既有 Claude/Codex 执行适配器继续通过一个 ExecutorPort 接入。执行任务保存 provider、model、adapter、runtime_profile、policy_snapshot、project 和操作身份。模型故障不会隐式切到其他执行端。[L5]

DSH 在 macOS 上默认是后台执行端。任务必须通过已核对应用包内的签名 Electron Helper 进入官方 CLI，不启动或激活桌面主应用；Helper 缺失时拒绝任务而不回退到 GUI 进程。DSH 桌面界面只能由用户显式打开，查看、配置和执行使用同一安装身份，但不共用启动方式。

工作者提交成果和自测，主脑或独立检查者核对实际文件与测试。独立验收不等于每个任务都多开一个模型；确定性检查足够时直接执行，确需模型复核时按已授权预算使用。生产系统支持多工作者，不要求本次开发会话额外建立多角色团队。

# 多 agent 协作设计

## 角色与权责

产品内的 agent 只有五类，职责互不重叠。任何角色都不能自我授权，也不能通过自然语言互相调用；协作只经受控命令、版本化记录和收据发生。

| 角色 | 谁担任 | 可以做 | 不能做 |
| 决策主脑 | 项目绑定的 Claude CLI 或 Codex CLI（原生 auto） | 调查 提交计划补丁 提出派发 提出人类问题 提出收尾候选 | 直接改交付文件 写 .model-desk 账户配置 运行 home 自行关闭目标 |
| 控制服务 | Python 控制内核与 GoalGraph／TaskGraph | 校验 授权 预留预算 建立唯一意图 记录收据 防复活 | 推理 生成计划内容 代替验收 |
| 执行者 | Pi DSH WorkBuddy Claude／Codex 执行适配器 | 在被派发的范围内完成任务并提交自测 | 改变计划 选择其他模型 接受自己的成果 |
| 独立检查者 | 确定性命令 主脑亲自运行的测试 或按授权预算使用的另一模型 | 对实际文件和命令输出给出 AcceptanceEvidence | 沿用执行者自报结论 |
| 人类 | 项目所有者 | 固定准则 回答例外 停止 恢复 授权费用 | 无（最高权威） |

决策主脑与执行者是不同的运行实例：主脑拥有目标，执行者只拥有一个任务。同一模型可同时被绑定为两种角色，但身份、会话和记录分开，不共享原生上下文。

## 协作通道

agent 之间不存在自由聊天通道。允许的信息流只有六种，每种都对应一条持久记录，消息流图只展示这些记录，不补画因果。

| 通道 | 方向 | 持久记录 | 关键保证 |
| 目标上下文 | 控制服务到主脑 | 轮次上下文与事件游标 | 只含受信归属和证据引用 不含密钥 |
| 主脑命令 | 主脑到控制服务 | plan_patch dispatch_ready needs_human completion_candidate | 乐观版本 依赖无环 项目归属 当前授权 |
| 派发 | 控制服务到执行者 | 效果回执 初始化清单 队列回执 | 同一操作标识只产生一次启动输入 |
| 成果 | 执行者到控制服务 | 任务结果 自测 文件摘要 | 结果不等于验收 |
| 验收 | 检查者到控制服务 | AcceptanceEvidence | 绑定实际文件摘要与命令 |
| 例外 | 控制服务到人类再回到任务图 | 决策项 答复 DecisionUse | 单次消费 只恢复受影响分支 |

原生 CLI 内部的工具调用、命令、文件变更与子代理活动是执行会话的诊断子节点，不构成第七种 agent 协作通道，也不获得控制权限。工作台只从已登记 Claude/Codex JSON 事件尾部投影有界节点和确定方向；不复制工具结果正文、文件内容或原生会话标识。`item.completed` 和匹配的 `tool_result` 才产生返回边，缺少回执时保持未知。节点没有 stdin、PTY、停止或设置入口；完整原文仍只能从所属已登记会话的只读检查器按需查看。

## 任务生命周期

一个任务经过：计划（主脑提交阶段）→ 就绪（依赖完成且无待决问题）→ 分支观察（实时授权 费用 STOP 文件范围）→ 派发（批准消费 效果回执 初始化 入队）→ 执行 → 结果 → 独立验收 → 通过或整改。每一步由控制服务读取领域事实决定，主脑只在回合内提出下一步。

整改是同一目标下的新子任务，保留父任务、证据摘要与整改次数；成功任务不随之重跑。验收不通过、预算内的替代实现和普通重规划由主脑自行处理，只有准则冲突、缺失关键事实、授权扩大、账户不足或有界核对仍未知才形成人类例外。

## 并发与隔离

并发有三层边界：目标内的就绪任务集合、有界派发器和资源租约。

| 边界 | 设计合同 | 当前实现状态 |
| --- | --- | --- |
| 就绪判定 | 依赖阶段完成 目标未停止 无待决卡 计划未被替代 | 已实现 stage_store.readiness 与分支观察 |
| 人类问题隔离 | 只暂停受影响分支 其余分支继续 | 已实现 每阶段一条 TaskGraph 分支 持久 interrupt |
| 有界派发 | 每项目工作并发上限 默认 1 可显式提高 | 已接入原队列：线程池 8，项目上限默认 1、可设 1–4；等待者也占线程 |
| 文件冲突 | 声明文件集合重叠的任务不得同时执行 | 同一安装共享持久资源库；重叠路径、嵌套项目与规范路径别名互斥，跨安装尚未统一 |
| 写入隔离 | 每个写入任务独立工作副本或文件租约 同目标一个集成所有者 | 公共 execute_task 租约持续到原执行体返回；Claude/Codex 临时副本写回增加基线版本核对、候选成果保留和逐文件原子替换；独立验收保留 |
| 共享资源 | 端口 账户 数据库按账户限流 | 账户桶固定上限 1，费用授权仍由原启动与请求围栏检查；没有通用端口／数据库租约 |

当前原执行队列通过进程内等待票据与同一安装的持久资源库组合准入：不同项目、不同账户桶可同时运行；项目默认串行。同原生提供商的执行登录共用一个桶，API 按主机保守归并，local 按模型；并非服务商核实的账户身份。设置在申请资源时取快照，在途较低上限仍约束后续准入。取消或目标 STOP 会退出等待，配置错误不得绕过租约。工作器登记真实进程身份后执行，POSIX 受管会话中仍有子进程或状态不可读时保留租约；macOS 还消费 kqueue fork 通知并围栏近期被 PID 1 重新托管的同用户候选。不同安装及任意内核谱系证明仍未完成；Windows 已按用户要求排除。崩溃恢复以独立进程被强制终止后的新进程接管为验收边界，不安排真实供电故障或硬件缓存级测试，不能称分布式、完整 OS 隔离或硬件级持久性已完成。

排队租约现须在父进程启动前与子工作器入口分别复核：项目规范路径、写入集合、账户桶及并发上限必须仍匹配。父进程在原 task.json 保存无凭据的 execution_lease 快照，子进程使用自己实际读取的模型配置核对；DSH/Pi、WorkBuddy、直接咨询、Aider 与原生 CLI 均接入。取消等待即使随后恢复授权也不能直接启动。拒绝仍走原队列恢复，不自动换模型或替换任务。该快照不是跨进程锁的持有证明；历史／直接调用且无快照的工作器保留原有准入边界。

Claude/Codex 共享 file_writeback：复制前记录声明文件的 SHA-256、权限与缺失状态，复制后核对基线；成功结果先存入原任务 capture 下的 proposed-files 与 writeback-plan.json。整批预检发现新建、修改、删除或权限冲突时，不覆盖原文件并保留候选；未修改的候选不覆盖后来的外部编辑。实际替换走原目标授权锁，逐文件原子替换并记录已应用列表。POSIX 替换在同步临时文件和原子 rename 后同步父目录，新建嵌套目录逐级同步；计划／回执首次发布与幂等重试同样同步目录。两文件生产恢复已验证第一文件持久替换后强杀独立控制器，新进程只补剩余文件；两个替身子进程的不同文件并行结果也已验证；`gpt-6-luna` 与 `claude-haiku-5-5` 已在一次性安装／项目中各完成一条公共生产执行、固定测试、回执写回和租约释放。整批写回仍不具备多文件全有／全无事务，也不能消除不遵守工作台锁的外部编辑器在末次检查后的竞争。阶段在各自副本测试通过不能替代合并后独立验收。DSH/Pi/WorkBuddy/Aider 原就地执行方式没有因此获得临时副本或此写回保护。

新原生编辑任务另有 writeback_protocol 与不可变 writeback-receipt.json，绑定固定输入、原调用、计划摘要及测试证据。现有 recover 接口识别后只恢复文件，不重新排队调用模型；恢复前核对进程退出、当前授权、文件租约和原队列身份。成功核对原队列与任务完成，仍待独立验收；回执不完整、测试未通过或证据改变则保留待核对。测试失败／超时保留不可应用的候选。详细状态、证据与限制见 `写回恢复协议.md`；这是显式恢复入口，跨进程强制终止后的接管已有专项验证，但并不提供整批事务语义。

`durable_leases` 已通过 execution_leases、lease_runner、lease_runtime 接入生产源码：reserved → armed → started → released，完整回执 CAS，不按超时或控制器退出释放仍在运行的工作器。子工作器登记不依赖父回执；文件恢复在同一资源事务内接管原代次，失败则回滚。工作器另将已观察后代的精确身份持久保存，关闭观察前进行末次核对；已知后代即使脱离会话也必须退出才能释放。macOS 在执行原脚本前同步注册 kqueue `NOTE_FORK`，事件触发后同时扫描确定后代与同一短时间窗内重新托管给 PID 1 的同用户存活候选；候选只阻止释放，不作为自动停止授权。强杀、缺失、中断或进程表不可读均不视为静止。该机制覆盖已验证的短暂父进程双重 fork 逃逸，不等同 EndpointSecurity 的完整内核谱系；并发无关进程可能被保守围栏，kqueue 也不提供子 PID。租约未释放时，阶段同步、独立验收、删除及 owner_epoch 移交均受保护。真实 Python 替身覆盖控制器退出、后台子进程、双重 fork、父启动回执失败与原恢复入口。原服务未部署；详细范围和平台限制见 `持久租约接线验收.md`。

租约库首次创建采用两阶段 identity marker。`initializing` 只证明该身份尚未对外准入；SQLite 在同目录临时库完整建立、同步并原子发布后，才把 marker 原子改为 `ready`。下一事务能恢复 marker 后未建库或建库后未晋级两种中断；ready／旧版 marker 对应的数据库丢失仍拒绝重建。只读状态不会推进初始化。Goal 在本地／持久租约等待期间被 STOP 时，公共入口将同一原队列收据结算为 blocked/recovery_pending，避免退出线程后遗留 queued 投递。

## 主脑移交

每个目标同一时刻只有一个主脑所有者。设计的移交流程：冻结新派发，核对原会话是否仍在执行，写入新的 owner_epoch，新主脑从领域库重建上下文后继续；旧主脑回合到达的结果只归档不据以派发。现已实现显式 handoff：仅活动目标处于 USER_PAUSE、无保护保持、无未结轮次及执行任务时允许。请求携带 request_id、expected_owner_epoch、expected_authority_epoch 与目标项目已启用的决策 model_id；原目标锁与数据库事务内核对双代次并更新时钟。旧记录 owner_epoch 视为 0；每次移交两种代次各加 1，原模型与会话写入 owner_history，新 native_session_id 置空。重复请求返回原回执，冲突请求拒绝；移交保持暂停、不启动 CLI、不改周期或未完成义务。原生轮次领取携带 owner_epoch，续租和回执核对两种代次，原派发继续以 authority_epoch 围栏阻止旧提案。面板暂停目标提供“移交主脑…”入口，之后恢复仍须显式操作。2026-10-23 已在一次性项目沿生产控制器完成 Codex → Claude → Codex 三轮真实原生调用：owner_epoch 精确递增两次，每次移交清空旧会话并保持暂停，恢复后新所有者从领域库重建；第二个 Codex 会话与第一个不同。DSH/Pi 不因此成为原生 goal runner 主脑。

Claude/Codex auto 主脑不再把原项目作为可写 cwd。每个 Goal 在 `.model-desk/goal-brain/<goal>/native-workspace` 保存稳定的隔离副本；每轮在没有活动主脑进程时从权威项目刷新，排除工作台记录、Git 元数据、运行 home 和链接。提示中的项目身份也改绑到副本，任务结果以有界 `answer/test/writeback/review` 字段提供，不向模型暴露原运行记录绝对路径。主脑可以在副本中使用原生文件与终端工具调查，但只有通过 schema 校验并经过 Goal 动作、授权、租约与独立验收链的结构化动作能影响原项目。会话只有在同一副本路径启动并留下绑定回执后才允许 resume；升级前的旧 cwd 会话安全换新，避免续接回原项目。副本随该 Goal 的主脑轮次记录参加永久删除。Codex 原生 `workspace-write` 与 macOS Claude 的附加 Seatbelt 写围栏已用真实模型核对项目外绝对路径；Claude `safe-mode` 单独使用时确实允许外部写入，因此不能作为隔离依据。macOS 围栏只开放副本、专用临时区和 Claude 会话状态写入，不限制读取；非 macOS Claude 仍只声明工具与应用级副本边界。

## 跨宿主一致性

Claude 与 Codex 作为决策主脑共用同一调度核心、计划协议、分支图、启动点授权和删除合同；Codex MCP 与 DSH loopback 两个面板入口共用同一人类答复与派发接口。宿主差异只存在于适配层：启动参数与权限模式的表达、事件格式（Claude stream-json 与 Codex --json）、是否有工具层记录保护（Claude 有 Edit 拒绝，Codex 依赖沙箱与提示）。现有公共 enforcement 报告按适配器与决策／执行角色声明 enforcement_scope，缺失能力显示未支持；模型详情页显示覆盖范围和限制。basis 固定 adapter_declaration、runtime_verified 固定 false，不把声明作为具体运行的隔离证明。完整映射与测试范围见 `权限约束声明.md`。

## 故障与降级

| 故障 | 行为 |
| 主脑回合失败或输出不合规 | 返回具体校验错误 受预算限制的有限修正 无进展指纹退避 |
| 执行者启动结果未知 | 保持 UNKNOWN 核对原运行 不重发提示 |
| 执行者成果不通过验收 | 主脑发整改子任务 达到整改上限形成一个人类例外 |
| 账户额度耗尽或费用授权撤销 | 资源守卫暂停派发 不换账户 不换模型 不买额度 |
| 用户 STOP | 递增 epoch 冻结派发 旧结果归档 不复活 |
| 检查点丢失 | 由领域事件重建分支 已有回执不重复启动 |

## 多 agent 验收条件

下列场景全部有可重复的自动测试，并另有原生实机验收后，才能称多 agent 协作完整：两个独立阶段其中一个等待人类时另一个照常派发并完成；同一问题的答复只恢复其受影响分支且恢复一次；STOP 之后迟到的执行结果只归档；启动结果未知时不重发；执行者自报通过但文件与测试不符时验收失败并发整改；撤销付费授权后快照期内的主脑与执行进程均不启动；两个声明了相同文件的任务不会同时执行（已有进程内竞争测试）；主脑移交后旧主脑的结果不派发（已有移交围栏测试）。这些行为已有离线测试；仍缺的部分按具体条目记录为原生实机或跨进程验收。持久化崩溃场景统一用强制终止进程模拟。

# LangGraph 控制结构

!FIG graph.png | 图一 拟议 LangGraph 控制结构。节点是控制机制，阶段内容由原生主脑动态生成。[R1][R2]

## 两层图而非固定阶段

GoalGraph 管理一个目标的观察、原生主脑回合、计划补丁、就绪任务与完成候选。TaskGraph 管理一个工作项的派发、结果核对、验收、整改和异常。图的控制节点稳定，任务阶段、依赖和数量是版本化数据，不能把“调查→编码→测试”写死成所有项目的流程。

GoalGraph 使用 thread_id = project_id／goal_id／graph_generation 的稳定编码；TaskGraph 使用独立任务身份。父图的某一人类问题不暂停整项目。需要人类的 TaskGraph 使用 interrupt，其他任务图照常推进。只有全部可推进工作都受同一问题阻塞时，目标进入等待；不在整个扇出批次的父节点前统一 interrupt。[R2]

就绪任务经有界派发器分成独立图执行；Send 可以表达一次已授权工作批次内的动态分派，但不能为绕过全局并发或人类问题隔离而无限 Send。不同任务的结果通过按 task_id 去重的 reducer 合并；并行分支不能同时覆盖同一标量状态。[R1]

# LangGraph 状态与恢复

## GraphState 合同

| 字段 | 含义与归属 |
| schema_version graph_version | 状态格式及图代码版本 |
| project_id goal_id task_id | 受信归属 不从模型文本继承 |
| authority_epoch event_cursor | 当前授权及已处理事件位置 |
| plan_revision policy_snapshot_id | 内容版本与执行依据 |
| ready_task_ids invocation_refs | 待推进任务与外部运行引用 |
| decision_refs evidence_refs | 人类事项和证据引用 |
| next_action reason | 控制下一步 不代替领域事实 |

图中只保存小型引用和必要判断，不塞整个原生聊天、日志、Key 或每轮完整文件。原生上下文压缩与 LangGraph checkpoint 是两件事；压缩前后均从领域存储重建目标、未完成义务和证据引用。

## Checkpoint 与领域数据库

LangGraph checkpoint 保存执行位置，领域库保存授权、目标、任务、决定和操作收据。跨库不能假装一次事务：先在领域事务提交可重放命令与 outbox，图记录其回执；重进节点按 command_id 读取原回执，不重复创建意图。checkpoint 丢失可由领域事件重建图；领域库损坏不能从旧 checkpoint 猜出最新用户停止。

采用 SqliteSaver 做单机持久恢复，MemorySaver 只用于测试。单守护进程持有每个图线程的执行权；多进程时还需要应用级锁和租约，checkpointer 本身不被当作任意跨进程调度锁。两个 SQLite 文件都放在本机用户数据目录，不放网络共享盘。[R9]

interrupt 节点恢复会重新执行节点前半段，所以只允许读或幂等地确认已有 decision_id；实际启动模型和外部写入不得放在无保护的 interrupt 之前。生产恢复以同一 thread_id 和经过版本核对的 Command(resume=...) 进入。[R2]

# 动态计划与主脑协议

## 结构化计划补丁

PlanPatch 包含 base_revision、reason、add_tasks、replace_tasks、cancel_tasks、dependency_changes 与 evidence_refs。任务内容含 objective、acceptance、declared_resources、candidate_bindings 和依赖；模型不能通过补丁写入系统控制字段。

普通拆分、合并、路线替换和错误修正由主脑自主提交。服务校验基线版本、依赖无环、项目归属、资源约束和当前授权，原子生成新修订。原任务及结果保留，不重写历史。运行任务继续使用其快照；重规划若要停止它，必须发独立取消命令并核对结果。

| 主脑输出类型 | 控制行为 |
| plan_patch | 校验和提交版本差异 返回稳定回执 |
| dispatch_ready | 对已就绪任务建立唯一派发意图 |
| needs_human | 建立或复用结构化决策项 |
| completion_candidate | 验证义务和验收证据 不直接关闭 |
| progress | 记录有效事实及下一步 不重建任务 |
| unknown | 有界核对原会话 不盲目再调用模型 |

模型输出不符合结构时返回具体校验错误，让原主脑自行修正；结构修正次数和成本使用现有预算，不能无界重试。若原生工具协议可直接提交结构化调用，优先于从自然语言或终端画面猜测。流断开、回合结束和退出码零都不等于目标完成。

图的重规划循环不是高频 heartbeat。每轮由真实进展或失败触发，保留无进展指纹；重复相同失败进入退避或一个异常卡，不生成无数任务。

# 唯一续跑与 TCAUTO

## 两个不同范围的时钟

当前开发会话的 Codex heartbeat 只负责唤醒开发继续；软件自身的 ContinuationController 负责产品目标续跑。两者不能同时取得同一个产品目标的派发权。开发 heartbeat 不读真实任务后代替产品调度。

每个目标一条 continuation，字段为 goal_id、interval_seconds、due_at、schedule_revision、authority_epoch。默认 30 分钟，自动退避只能增大周期。错过多个周期只做一次资格检查。重启恢复原记录，不重建同目标第二条时钟。[T1]

任务完成事件可以驱动已经运行的协作流水线处理结果；周期续接用于失联观察和目标再次检查。两者分别标明 trigger_kind，不能用频繁伪造“事件”绕过周期。在资源暂停后的周期恢复仍遵守已有 due_at；用户明确“现在继续”是新的控制指令。

隔离实现中的来源事件与原阶段同步／人类答复同事务提交，在原 continuation claim 中一次绑定。每批最多 64 项，保存标识、状态和摘要；主脑上下文包含精确来源。自身审核变化归入当前轮，避免自触发。退避与资源恢复通过 event_not_before 保留等待时间；事件轮不重设周期，暂停、STOP 和旧 epoch 不自动复活。

这一接线沿用生产 GoalGraph 与公共执行回调。原队列确认、安全补投、新托管任务的初始化清单恢复以及生产 TaskGraph 的阶段分支中断／恢复均已接入。历史无原轮次归因的任务保持周期路径，事件本身不授予费用或验收权限。

## 用户意图与资源状态

user_intent 为 RUN、USER_PAUSE、STOP。资源 hold 单独保存原因、观察值、阈值来源与可自动恢复资格。低水位仅解除原资源守卫，不解除用户暂停、异常待决或停止。用户停止更新 epoch，旧事件、旧租约及旧恢复证明失效。

暂停／停止先冻结新派发和受控工具，再提交原生 interrupt，观察真实执行状态。原生 CLI 已在执行的动作可能完成；必须核对，不能把 SQLite epoch 说成能瞬间撤销全部原生或远端副作用。[T1]

目标实现、保存、分析、独立验收、允许清理分别记录义务。全部有效义务完成后才正常关闭唯一续接；用户取消的义务标为取消，不永久阻塞。用户要求撤钟则按其范围立即执行，不能以收尾未完强行恢复。

# 执行身份与故障防重

## 发出意图和真实效果

Invocation 保存 operation_id、task_id、attempt_id、native_session_id、native_turn_id、runner_instance_id、PID 出生标识、worktree_id、event_cursor 和状态。不能凭 PID 单独中断或恢复，也不能把项目中的最近会话作为续接对象。

最终派发合同要求在事务中校验目标 epoch、任务修订、预算、资源租约与当前策略，并写 invocation 和 outbox。进程启动使用同一 operation_id。消费者将 intent 从 pending 原子认领后执行；重复消息返回同一回执。

| 崩溃位置 | 恢复方式 |
| 事务提交前 | 没有有效意图 可重新处理原命令 |
| 提交后 启动前 | 领取同一 outbox 续同一意图 |
| 已启动 回执未落库 | UNKNOWN 查询原会话或运行器 不重新发 prompt |
| 结果已落库 checkpoint 未写 | 图重入读取已有回执 不重跑执行 |
| 用户停止后旧结果到达 | 归档真实结果 不据此派发新工作 |

外部效果只能通过目的端幂等键、原生会话查询或可核对收据防重，不能承诺任意 CLI 副作用恰好一次。UNKNOWN 不自动算失败；有界核对仍未知时提交一个人类异常项，保留真实不确定性。[R2][T1]

## 已落地的原队列恢复与剩余窗口

本实现复用原项目 SQLite、原 ThreadPoolExecutor 和 continuation 扫描器。新托管任务明确写 queue_protocol=1；所有任务文件初始化完成后保存队列准备回执，再入队。回执绑定原项目、目标、阶段、task_id、原主脑轮次、授权代次、原派发请求和实际启动输入摘要。原任务与 prompt 各限 256 KiB，回执限 16 KiB；不把任务正文、账户密钥或输出放入队列。

| 持久状态 | 可以做什么 | 禁止做什么 |
| --- | --- | --- |
| READY | 通过当前授权后提交原线程池 | 新建替代任务或改变原模型与输入 |
| QUEUED／CLAIMED | 旧运行器确证退出后，用新 token 补投同一任务 | 把存活、PID 无出生证明、进程表不可读当作退出 |
| ARMED | 核对本次真实启动与结果 | 根据缺少 PID 判断未启动并重发 |
| STARTED | 保留精确 PID 与创建身份；继续观察原结果 | 仅凭服务重启重新发送模型请求 |
| DONE | 原 launcher 的 wait 已返回，按原任务结果与独立验收继续 | 把队列完成当作模型成功或验收通过 |
| BLOCKED／UNKNOWN | 保存原输入、恢复原因和未决义务；明确无启动证据时仍走原恢复入口 | 用人工确认按钮越过未知启动 |
| CANCELLED | 保留取消记录，撤销未启动 token | 资源恢复后自动取消人类停止 |

每次投递 token、所有者和状态变化都写原 stage_log。入队回复异常时，在原目标锁内撤销旧 token；ACK 只确认投递，不把已经运行的状态回退。回调和真实 Popen 前再次验证输入与当前授权。重复回调无新启动；输入改写、损坏或协议降级留下可检查的恢复记录。启动时，精确确认仍存活的 launcher 与对应阶段保留运行状态。

恢复每批最多检查 64 个原队列项，不重建 continuation，不改变周期、due_at 或目标授权。它与此前 CLI 适配器在实际模型 Popen 处的启动围栏是两层边界：前者管理 Python worker 投递，后者管理模型调用。两者都不能证明任意远端副作用恰好一次。

新托管任务在原阶段认领与批准消费的同一事务中保存初始化清单，再操作文件和父整改记录。清单包括完整原输入、prompt、原模型／会话、费用初值和工程习惯快照，最多 1 MiB；存于原项目私有数据库，公开日志只存标识与摘要。初始化只有 PENDING、READY 两个状态，READY 与队列准备回执同事务提交。

文件先写临时文件并 fsync，再发布到尚不存在的目标。已经存在的相同内容可重用；冲突内容和路径别名拒绝覆盖。恢复使用原请求定位同一清单，核对当前 STOP、授权、阶段与输入后，补齐同一 task_id。初始化完成后不再用旧清单覆写运行结果。跨数据库和文件系统仍不是单次原子提交；这里实现的是可核对的分步恢复，验收边界为进程强制终止后的新进程续做。

整改清单还保存原父任务及审核证据摘要。原 review.lock 内重新核对后幂等标记同一子任务；只有该子任务的派发时间／标记允许作为恢复差异，不重置整改次数、模型或会话。认领后的失败不能被归类成没有效果的前置拒绝。没有清单的历史任务、内容冲突或缺乏原始证明仍保留 UNKNOWN，不反向补造初始化证据。

生产 TaskGraph（host_branch／task_graph_bridge）、主脑与执行器启动点的授权重查、持久记录的完整删除已在 0.2 落地并有离线测试。租约初始化、多文件写回和持久删除提交后的恢复均有独立进程退出或 `SIGKILL` 证据。Claude 主脑与执行器现由 macOS Seatbelt 约束写入副本和专用状态目录，Codex 使用原生 workspace sandbox；两者都已实测拒绝项目外绝对路径写入。边界：macOS Claude 写围栏不提供读取隔离，非 macOS Claude 未做原生验证。前端外壳现已完成并通过八组隔离浏览器验收；DSH 最小真实只读任务和独立 DeepSeek API Key 余额通道已有历史真实证据，本次不重新读取账户。Pi 适配已由用户取消当前安排；Windows、真实断电和硬件缓存验证不在范围。发布候选和本轮运行态证据见《最终收尾验收》。

## 隔离与共享资源

每个写入任务使用独立 worktree 或明确的文件租约，同一目标一个集成所有者。worktree 不隔离端口、账户、数据库或外部服务。资源租约包含相应共享对象，账户并发按账户限流。进程环境只传必要值，不复制整个运行目录、配置、记录或凭据。

# 持久记录的清理合同

永久删除沿用现有预览与明确提交入口。预览须覆盖任务、关联目标／阶段、原动作与续跑回执、初始化清单、队列、来源事件、批准消费及图 checkpoint 的引用与实际文件；不能只删除 runs 文件夹后声称提示词全部清除。活动执行、未知调用、未结算费用或有效未完成义务必须先核对，不能删除恢复所需证据。已发生费用总账与账户配置继续保留。

提交前重新核对同一预览指纹与实际进程，按原日志记录可恢复的清理步骤；数据库提交和文件擦除不伪装为跨资源原子事务。中断后只完成已授权的同一清理，不能扩展到其他项目。0.2 已落地：核心 host_purge 盘点目标、任务与主脑轮次所属的全部持久行，task_history 以真正保存该项目行的数据库为唯一提交点并同事务写日志，其后的旧库重复行、checkpoint 线程和目录清理幂等完成，recover 按日志续做；删除连接启用 secure_delete 并截断 WAL。活动或 UNKNOWN 轮次、待核对请求、未完成队列与初始化、未结算费用和未知调用都会阻止删除。独立删除进程已在日志提交而 checkpoint 与暂存目录尚未清完的边界被 `SIGKILL`，新进程通过生产 `recover()` 完成同一清理。文件系统层面的擦除不保证，SSD 与备份可能保留副本。

# 人类待处理与验收

## 默认自主 仅处理例外

人类列表不是每次计划的批准队列。测试失败、预算内的替代实现、普通重规划和确定性检查由主脑自行处理。准则冲突、缺失关键事实、授权范围扩大、账户不足或有界核对仍未知，才形成决策项。

决策项保存 question、reason、evidence、options、recommendation、affected_task_ids 和 still_ready_tasks。去重键来自问题主体及相关约束。相同阻断无变化保持原卡，用户可以逐项回答，不能以“全部同意”越过不同事项的授权范围。

答复绑定 subject_hash、相关 artifact_hash、阶段计划内容摘要、policy_revision 和 epoch。无关分支修订可继续；相关产物或授权变化使旧决定失效，并说明具体差异。答复只恢复该任务图，其他就绪任务不用等待。

新例外卡的范围为受影响阶段及完整上游依赖，同时观察原项目的任务、验收与交接记录。同一张卡涉及多个独立阶段时，从一次有界观察生成各阶段的内容摘要；一个阶段的正常进展不会消耗另一个独立阶段的批准。旧卡及最终审核保留整目标范围。

批准消费与原阶段派发在同一项目事务中保存，回执绑定 decision_id、stage_id、task_id、原问题摘要和授权。原任务的幂等重入沿用该回执；新任务需要新的有效批准。消费后允许该任务修改自身产物和生命周期，仍核对提案、上游输入和当前授权。明确的原任务恢复通过原阶段认领入口重新核对，执行器启动时不能补造消费记录。消费记录不替代续跑权限、费用授权或独立验收。生产任务事件与阶段分支已接同一 GoalGraph／TaskGraph；答复只恢复其受影响分支，恢复在下一原轮次发生。这项派发边界不代替整条恢复链的原生实机验收。

## 独立验收

AcceptanceEvidence 包含检查对象、文件或产物摘要、实际命令、测试结果、检查者身份和覆盖范围。自报完成不是验收事实。验收不通过时形成具体整改任务，成功任务不跟随重跑。需要用户做主观选择时，验收节点创建决策项；否则按用户准则自主判定。

主脑可以提出收尾完成，关闭服务需验证有效义务、最新策略、无活动运行器和交付回执。失败与用户停止走部分交付，保留未完成范围，不套用正常成功封存。

# 全局工程习惯与权限

## 右上角规则入口

三种模式为关闭、全局默认、项目覆盖。面板展示模板名称与版本、有效范围、覆盖差异、冲突、活动目标使用的快照以及主脑是否确认加载。治理状态直接读取持久 GoalGraph 的 snapshot/native 阶段：分别显示尚未加载、已捕获待回执、已加载并确认、配置已更新待下一轮或回执不可读，不能以“设置已保存”冒充在途主脑已经采用。读取只提取策略快照 ID、版本和阶段状态，不反序列化整份主脑上下文。默认不开启一个用户从未选择的全局规则包；已明确启用的选择在后续项目中可继承。保存偏好不启动模型。

全局模板只迁移方法，不包含其他项目的路径、账户、阈值、任务结论或进度。安装级 `engineering-policy.json` 只保存全局开关、模板选择和全局补充方法；项目模式、选择及自定义规则保存到该项目自己的 `.model-desk/engineering-policy.json`，使用独立项目版本。升级前保存在全局 `projects` 映射中的覆盖只读兼容，在用户下一次显式保存该项目设置时先发布项目文件、再清除全局残留；读取不会创建项目记录。TCAUTO 工程习惯作为可选模板，续跑控制合同则由产品程序实现，不能仅塞入提示词便称完成。[T1][T2]

## 策略优先级

最新明确用户指令、当前项目约束和所选全局模板共同形成 EffectivePolicy，保存每一项来源。项目成功标准不能被模型计划降低；过期模板不能覆盖用户的新停止。运行快照用于追溯，当前撤权和预算收紧在新派发及受控工具入口重新检查。

原生 CLI 在一次回合内可直接使用工具，控制层若没有接入权限钩子、MCP 受控工具或执行代理，就只能保证派发边界。产品必须按 adapter 报告 enforcement_scope，例如 dispatch_only、controlled_tools、native_sandbox；不能一个“全局启用”勾选就宣称所有宿主相同。

共享行为同时验收 Codex、Claude，并兼容现有 Codex／DSH 主脑接口。缺少适配器的能力显示未支持。auto 仍允许原生分类器拒绝操作；拒绝是实际执行事件，不通过静默降级为 bypass 消除。[R8][L5]

# 数据模型与 API

## 数据归属

全局目录保存非秘密连接引用、项目注册、全局工程模板和界面偏好。每项目 `.model-desk` 保存该项目的工程习惯覆盖；每项目领域库保存目标、计划、任务、调用、决定、证据和费用归属。全局配置不再新增项目绝对路径或项目自定义规则。凭据沿用现有安全存储，checkpoint 与事件不保存密钥。跨项目索引只保存必要摘要，不读取其他项目原生聊天。

| 实体 | 必要标识与版本 |
| Project Binding Connection | 规范化项目 ID 关联版本 账户引用 |
| RuntimeProfile PolicySnapshot | 请求配置 有效配置 来源摘要 不可变 ID |
| Goal PlanRevision Task | 目标 epoch 计划基线 任务依赖和替代关系 |
| Invocation Runner Receipt | 操作 ID 原生身份 出生标识 回执摘要 |
| Decision Evidence Obligation | 主体摘要 答复版本 检查证据 收尾状态 |
| DecisionUse | 原项目内的决定 阶段 任务及授权摘要 随阶段认领原子提交 |
| Continuation Outbox Event | 唯一目标时钟 聚合序号 幂等事件 ID |

## 主要 HTTP 接口

| 接口 | 合同 |
| GET /v2/projects /connections /accounts | 只读快照 不隐式刷新 |
| POST /v2/catalogs/refresh /accounts/refresh | 显式元数据读取 有界且账户去重 |
| POST /v2/projects/{id}/bindings | 建立或修改角色关联 需要版本 |
| POST /v2/goals | 目标与准则 建立快照 不任意生成授权 |
| POST /v2/goals/{id}/plan-patches | 主脑提交 乐观并发和依赖校验 |
| POST /v2/goals/{id}/pause stop resume | 最新用户控制 epoch 防复活 |
| POST /v2/decisions/{id}/answer | 当前主体和单次消费 答复幂等 |
| GET /v2/events?after={seq} | 可续接事件流 断线按游标追赶 |

所有写命令有 request_id、expected_revision 和受信项目。相同 ID 相同正文返回原回执；不同正文拒绝。错误区分版本冲突、权限不足、资源暂停、参数不支持、执行未知和服务不可用，不用统一“失败”推动盲目重试。
