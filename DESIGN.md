# Model Desk design system

## 1. Atmosphere & Identity
A calm, neutral desktop workbench for people who are not workflow specialists. A tonal left rail holds the project tree, the account summary and global entries; the main surface is a sticky project header, five tabs (概览 / 目标 / 任务 / 模型 / 设置) and bounded cards. Ink-black primary buttons, hairline borders and one status palette carry the identity; there are no gradients, decorative illustrations or promotional copy. User-facing text avoids internal terms (lease, epoch, side-effect boundary); those stay in tooltips or evidence views where they are needed.

## 2. Color
Tokens live in `panel/style.css` and are redefined for dark mode under `html[data-theme="dark"]`: `--bg`, `--surface`, `--inset`, `--sidebar`, `--ink`, `--ink-soft`, `--muted`, `--faint`, `--line`, `--line-strong`, `--row-hover`, `--row-selected`, `--accent`, `--focus`, plus a terminal pair for the CLI inspector. Status uses one palette, each with a tinted background: `--st-run` (running/starting), `--st-ok` (ready/done), `--st-wait` (waiting/stale/unavailable), `--st-review` (needs a human), `--st-unknown` (unknown, purple so it never reads as failure or success), `--st-bad` (failed/conflict), `--st-off` (stopped/idle/disabled). Legacy `--green/--orange/--red` alias these. State classes `.s-<kind>` set `--c/--cb`; `.sdot`, `.stag`, `.badge`, `.flag` and tree labels consume them. Neutral defaults for `.stag/.badge` are declared before the state classes so a state class always wins.

## 3. Typography
System stack (`--font`: -apple-system, SF Pro Text, PingFang SC, Hiragino Sans GB, Microsoft YaHei, system-ui) and `--mono` for paths, model ids and CLI output. Sizes come from `--fs-xs/sm/md/base` and 18–24px headings; numbers use tabular figures. The 小/标准/大/特大 font-scale setting zooms the document and every 100dvh/100vw geometry divides by `--ui-scale`. Model ids and paths truncate with the full value in `title`; labels wrap.

## 4. Spacing & Layout
Spacing tokens `--desk-s1`…`--desk-s8` (4–32px). Desktop shell: `--desk-sidebar` 284px rail + `minmax(0,1fr)` main, each with its own bounded scroll; 256px rail below 1120px; below 900px the rail becomes a dismissible drawer, the header is no longer sticky and the page scrolls naturally. Overview is a stat-tile row plus goal / project-model / recent-task cards; Models is a list + inspector; Tasks is list + detail. Horizontal page overflow is prohibited at every width (checked at 1440, 1280, 1024 and 375).

## 5. Components
- **Project tree**: native details/summary folders (project → 决策模型 / 执行模型 → model rows). Each row has a status dot plus text (已启动 / 运行中 / 已就绪 / 待核对 / 已停用 …), 默认 marker and a ⋯ button that only claims space on hover, focus or selection for fine pointers. Arrow keys, Home/End, Right/Left (open/close), ContextMenu and Shift+F10 work over visible rows; children of collapsed folders are skipped.
- **Account summary**: one row per source (Codex, Claude, DSH wallet, DeepSeek API) with value, meter, source tooltip, local update time and an explicit 过期 / 未读取 / 读取失败 / 不可用 state; the full dialog adds per-window detail and source text. Unknown never becomes 0; a failed read never shows an old balance unless the backend marks it stale. Beijing-time stamps carry a 北京时间 label.
- **Model inspector**: header with status tag, primary actions (停用/启用, 分派任务, 查看消息流, 编辑连接, ⋯), honesty notes (enabled ≠ running), collapsed permission constraints, effort options from the native catalog, Codex fast only where the catalog allows it, context budget and auto-compact fields, the saved snapshot and a sticky save row. Decision-model copy speaks of rounds, execution-model copy of tasks.
- **Project execution settings** reuse the inspector's labelled number input, explicit save, inline error and dirty-draft preservation. The concurrency range is 1–4. A separate read-only waiting list names each task and its current resource reason, and may refresh without replacing the settings draft.
- **Goal workbench**: goal picker, status card (status tag, cycle, next wake, brain model name, round, controls), review banner, an interaction bar for `/btw` (read-only progress) and 插入最新需求 (radio cards for 增量需求 / 方向调整), plan progress and a numbered stage timeline whose dependencies read “接在步骤 N 之后”. A disabled 立即推进 reads 本轮进行中.
- **Tasks**: rows show glyph, title, model · source · phase, a flag line (write-back state, review result) and a status badge with duration. Write-back tags: 写回冲突 · N 个文件, 写回已暂停 · 成果保留, 候选待写回, 等待原生结果, 测试未通过 · 未写回, 需求已更新 · 不写回, 已写回.
- **Execution endpoints & CLI**: per endpoint enable switch, three-state availability, installed/latest version with when it was checked, signer (host app vs native), DSH background-only note, and update actions gated with a visible reason while tasks or brain rounds run.
- **All-projects view**: an explicit mode that shows only the task list with each row's project name; goal, model and settings tabs and project actions are hidden because they need a bound project. **Engine rows** show current model, wallet and status from the same shared facts as the endpoint settings. In the narrow sidebar the default model is marked with ★ instead of text.
- **Unbound and offline states**: without a bound project the main area offers a project picker (or first-run steps when there are none). When polling fails the header shows 连接已中断 and a notice that the page holds the last data, which is not the current state.

## 6. Motion & Interaction
Dialogs fade in over 160ms; controls use short color transitions only; `prefers-reduced-motion` removes all animation. Polling is unchanged (2s live / 10s idle, stopped while hidden); DOM writes are deduped and modules re-render from cached snapshots between throttled reads so no extra requests are made. Async actions disable their trigger at once; outcomes arrive through refreshed data and concise toasts. No provider call happens on render or polling; account refresh, catalog reads and CLI checks are explicit actions.

## 7. Depth & Surface
Tonal rail, white (or dark) cards with hairline borders and a soft card shadow, a stronger pop shadow for menus and dialogs. Radii: `--r-sm` controls, `--r-md` inputs and facts, `--r-lg` cards, 16px for the welcome card. Status colors appear as dots, tags and a role-colored top border on flow nodes; there are no decorative accent stripes.

## 8. Accessibility Constraints & Accepted Debt
Native buttons, details, dialogs and form controls; tabs use role=tab/tabpanel with roving tabindex; menus use role=menu with keyboard wrap, Escape and focus return; visible focus rings; 44px targets on coarse pointers; every state has text as well as color. Inline styles are avoided (CSP `style-src 'self'`); widths such as meters are set through CSSOM custom properties. No accepted new accessibility debt. Offline fixture checks are not native host acceptance.

## Message-flow extension

The flow view reuses the existing shell, neutral tokens and context-menu primitive. SVG edges and DOM nodes share one bounded graph viewport; the output inspector owns a separate bounded vertical scroll. Double-click and Enter open the same read-only inspector. A native-events view is labelled separately from a PTY mirror. No animated edges by default. Node movement changes local view state only. Every graph has a keyboard-accessible textual list from the same projection. Runtime controls reuse existing command routes and are unavailable until their adapter reports support. This section describes the implementation contract; the real CLI and rendered UI are not yet accepted.

The optional flow dialog uses a list-detail structure inspired by [StyleGallery's list-detail pattern](https://github.com/changeroa/StyleGallery/blob/main/patterns/split-sidebar/list-detail.md). Its shell is bounded to 88dvh; the graph and output each own their named scroll region. Below 900px the inspector follows the graph in document order; textual mode is the initial view, the scene shrinks to its content up to 45dvh, and explicit output inspection scrolls to the inspector. Dialog geometry accounts for the existing UI zoom setting. The dialog uses existing surface, line, ink, muted, focus and spacing tokens. New geometry tokens: dialog width 1440px, graph minimum height 320px, inspector minimum width 300px, node gap 56px, node minimum height 96px, output minimum height 240px. Nodes are cards with a role-colored top border and in/out ports on a dotted canvas; the three lanes fit without horizontal scroll at a 1280px window. Diagram nodes are buttons inside reusable session rows; selected and unknown states use tonal fills and text. The textual mode exposes the same sessions and directional message counts without SVG.

Context menus adopt keyboard wrap, Home/End, Escape, outside dismissal and focus return from [beui.dev's context-menu mechanism](https://beui.dev/r/context-menu/raw); no source is vendored. The existing 150ms opacity feedback remains, with no positional motion under reduced-motion. Controls name their scope: goal pause/stop affects the goal; task stop affects the selected task. Editing model settings affects future work and does not mutate a captured launch snapshot. Native output is inert text with a 32 KiB tail and an explicit omitted-byte count. There is no stdin, terminal escape execution, hidden model dispatch or polling when the dialog/page is hidden. Initial execution adapters without captured output report that limitation rather than inventing a terminal.

## Goal file authority

The criteria dialog uses the existing labelled-select and textarea primitives. A new goal starts with Project scope; AI chooses concrete files for each stage. Selected files reveals a finite list, and an empty selected list means no edits. Existing goals retain their recorded choice; legacy records without the new field show Selected files. Changing the selector only reveals or hides the draft list; saving is the explicit authority mutation. The goal summary names the active scope rather than presenting an empty whitelist as project permission. Runtime records remain excluded in either mode. No new colors, animation, dependency or dialog pattern is introduced.

## Original-round reconciliation

The existing inbox includes unknown or revoked original rounds. Its detail is a native dialog using the existing governance surface, typography and spacing. One body owns vertical scrolling between a fixed heading and footer, following the spatial mechanism of [scroll-body-shell](https://github.com/changeroa/StyleGallery/blob/main/patterns/viewport-shell/scroll-body-shell.md). There is no new top-level management page, dependency or polling loop. Body/caption/section sizes are 17/15/18px below 600px; touch actions remain at least 44px. Long identities and declared paths wrap and remain selectable. Stage files are explicitly labelled as declarations rather than a full workspace audit.

The nearest interaction reference is [beui.dev's center modal](https://beui.dev/r/center-morph-modal/raw), consulted for focus restoration, Escape dismissal and controlled open state; its code, animation and dependencies are not copied. The heading receives initial focus. Notes persist in memory through dismissal and a single-modal handoff to the read-only flow view, then clear when the project changes. Evidence refresh preserves notes and invalidates the checkbox when its subject changes. Loading, blocked, ready, stale/error and saved-decision states share one component. Submit requires complete evidence, nonempty notes and explicit confirmation. Success displays the saved human decision and the preserved pause/stop state. It does not accept stage quality. Shared CSS is unchanged; the component reuses its tokens and adds no motion.

The actual temporary-project UI was exercised for cancellation, stale evidence, flow return and successful disposition. 390px iframe component widths and current 704px page captures cover light/dark top and scroll-end states; these are not native mobile emulation or a complete desktop viewport matrix. Independent visual approval and native host acceptance remain pending.

主脑移交沿用治理对话框：仅暂停目标提供入口，原生 select 选择当前项目决策模型，明确“移交并保持暂停”，失败在表单内展示。保存不触发恢复；项目切换关闭表单。390px 与深浅色沿用现有响应式样式，不新增动效或视觉依赖。

权限约束采用模型详情里的原生 details/summary，默认折叠；沿用 inspector-settings 的间距和分隔线。展开内容按“配置的机制／覆盖范围与限制”显示，不新增状态颜色或后台轮询，不把已就绪与已验证隔离合并为一个标签。未知声明显示未支持。

任务资源核对复用 route-note、detail-facts、field-hint 和原生按钮。只有点击“核对资源与写回”才读取进程和文件证据，不加入轮询。结果标注核对时间、租约阶段、受管会话证明范围与逐文件状态；异常显示未知，绝不显示为空闲。切换任务／项目或原任务代次变化即丢弃旧结果。保存文件的恢复按钮明确“恢复文件写回”，保留原确认和后端授权复核；读取证据不释放租约、不启动模型，不代表允许执行。

持久租约任务待恢复时提供“停止任务并保留成果”，取消后若资源未释放则提供“重试停止残留进程”；沿用secondary按钮和session-note，不增加弹窗或轮询。明确取消后不能恢复写回，信号已发送不等同于退出已确认；结果分别显示资源已释放／仍待核对／未知。
