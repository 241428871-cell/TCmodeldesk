# Optional Model Desk collaboration

At each user turn, before substantial work, run `@ROOT@\.local-worker\venv\Scripts\python.exe @ROOT@\.local-worker\workflow_settings.py --status`; never start a service for this check. Missing/unreadable settings, launcher or `enabled=false` means ordinary Codex behavior and no automatic service or worker start. Explicit panel/worker requests remain allowed. Re-read before every automatic dispatch; disabling does not cancel running work. Preserve settings and permissions.

Before task detail in the first response, run `@ROOT@\.local-worker\collaboration_status.py --project "<trusted calling project>"` with that Python and show `user_signal.text`; repeat only when status changes. It is read-only. errors mean not ready, and enabled alone is not ready.

When enabled, use the chosen model's saved execution Agent (`default_agent`: DSH or Pi), or global `execution_agent` only when the model follows that default. Omit `--engine` normally; explicit engine means a deliberate task override. Route each final model candidate independently. Default changes never switch queued/running/continued/rework/reused sessions; Pi does not load DSH presets or nested agents. Codex owns clarification, consequential decisions, capability/risk judgment, routing and independent acceptance. Workers own investigation, design, implementation, tests and correction. Send goal, scope, constraints and decidable acceptance after minimal orientation, not a solved patch or entire chat. Keep trivial tasks and core high-risk decisions with Codex. The 30% responsibility target is approximate, not a token quota.

Quality first. Treat public capability notes as claims and include only judged-capable candidates. Estimate input from relevant files/history/tools. Never silently substitute model/engine/provider, bypass budgets or retry beyond one corrective round. Paid work requires `paid_allowed`; `enforce_paid_budget=false` and `enforce_model_call_limit=false` disable only those optional ceilings. Never raise/re-enable them silently. Runtime defaults to `timeout=0`; silence is not cancellation authority. Never read/expose secrets.

After the local desktop completion path passes diagnostics, prefer `--notify-on-completion` with the trusted project and read `@ROOT@\.local-worker\workflow-guides\waiting.md`. Announce waiting only after listener startup; end the turn, let the watcher wait, then independently review its one message. Batch before subscribing; never overlap batches. Distinguish waiting, execution ended/reviewing, accepted/completed and attention. Other hosts or unavailable bridge use quiet `--wait`; use `--progress` only on request or for diagnosis. Resume the same session/cell with bounded waits up to 60 seconds and batch tool-only waits. Do not repeatedly inspect records/logs/source or duplicate investigation. Reattach a lost waiter with `dispatch_task.py --wait-task <original-id>` without dispatch. Unknown notification never authorizes resend or redispatch.

Executor `completed` is not acceptance. Inspect relevant changes, since edit scope is not an OS sandbox; run minimal meaningful checks and require independent evidence for every criterion. Self-reports are claims. Record acceptance with review_task.py; for main takeover preserve raw failure with `--final-accept`. Allow at most one automatic rework; after another failure record `--block` and decide escalation. Records are workflow evidence, not cryptographic proof.

Project identity comes only from the trusted calling project absolute path. Bind panel opens with URL-encoded `?project=` or the MCP project argument; unknown/ambiguous identity stays unselected. Never infer identity from service cwd or another tab. Each project's `.model-desk/records.db` and `runs/<id>/task.json` own history; global project-index.json is only a locator. Exclude `.model-desk` from default search/index scans (not an OS sandbox). All-projects is explicit; model/account quota/day budget are global. Never initialize Git for a button. Human verification is required for native entrypoint visibility.

For an active Model Desk Goal, preserve both live interactions through model-visible `goal_interact`. Exact `/btw`, optionally followed by query text, is read-only: return its actual goal/clock/plan summary without service, model, continuation or dispatch. Insert any new instruction that changes the Goal through the same tool as `requirement` or `direction_change`; chat context alone is insufficient. Do not kill the current subprocess or revoke its lease. The action fence supersedes remaining effects from older requirement revisions; the next safe brain round reads the durable update. Resolve the Goal automatically only when exactly one is active; otherwise require its ID. `/stop` and `/pause` remain controls, never requirements.

Dispatch a stage only after prerequisite independent acceptance. Required handovers verify real file hashes, task/stage identity, same project/goal and dependency; missing/stale references block dispatch. Cancelled stages/goals remain cancelled; completed/cancelled goals cannot dispatch. `Recovery_pending` is never silently re-sent. Every stage/new task/rework gets a fresh selected-Agent session unless `--reuse-session` is explicit. Existing valid mechanisms remain authoritative.

Execution models must not modify `.model-desk` records or put business artifacts there; only controller code maintains task/log/acceptance/handover records. Never evade a refusal through another tool, script or provider. DSH/Pi use verified tool-argument guards, not OS isolation; arbitrary script targets remain a documented limitation. Controller records stay in the owning project.

Nested delegation requires all three: independently measured exact model/executor/preset/version identity, explicit user policy, and expected task benefit. Home/local never gets a child; unknown/stale/unmeasured modes stay denied. Paid does not imply capable; default allow is not task authorization. Child cost is part of DSH aggregate usage, not a separate measured invoice.
